# 临床契约 → 门诊计划 → 流利底稿 → 失流计划 → 转录 JSON

## 总目标与分层

任务不是把线上问答逐句改口语，也不是在通顺稿上随机插入「嗯呃」。工作拆成两个彼此独立的决定：

1. **对话如何自然推进**：门诊行为、追问顺序、人物表达习惯。
2. **哪些位置会自然失流**：犹豫、重复、重启、自我修正、残句、话题前置。

这对应 Yang 等人（EMNLP 2020）的 Planner–Generator：先由 planner 决定失流类型和位置，再由 generator 实现具体文本；相较随机插入或重复，更接近真实失流分布。LARD（Passali et al., LREC 2022）把 repetition / replacement / restart 程序化，但它面向英语句子级数据，不懂医疗事实、角色差异或多语对话，**只作类型参考，不得作为主生成规则去机械插词**。

工作链路固定为：

> 原始线上文本 → Clinical Contract（原子事实 + `fact_xx` + `FACT_SETS`）→ Encounter Plan（`TURN_PLAN` + 激活状态）→ Spoken Base（逐轮许可）→ Disfluency Plan → 最终 JSON → 逐轮溯源校验

保留主问题、症状与病程、已有诊断/检查/药物、医生解释、治疗、缓解、预防、生活方式、忌口、随访和关键否定/条件；不保留原话、原轮次、原句法或原有问答顺序。Stage 1 之后默认只读上一 stage 文本。**例外：** Stage 3 与 Stage 3 repair 可看紧凑 `[SOURCE_TURNS]`，且仅当已许可 fact 的契约表述不准或表达不清时用来校准落地措辞；不得当第二病例源，不得加新事实，不得照搬原轮次/原句法。追溯链必须可走通：

```text
最终第 n 轮 → Spoken Base 第 n 行 → TURN_PLAN 第 n 项 → fact_xx 或 listener_response → Contract / 原始证据
```

最终原则：对话的自然感来自**成对人设下的即时反应、有限信息的逐步激活、可承受的表达压力**，而不是强制轮流、随机桥接、整句空转 echo，或对每轮平均加失流。要模仿门诊 ASR 转写：短轮、半句接话、交替推进，不是文学对话简写，也不是清单式导演。

**可见性总原则：** 原始输入和 Clinical Contract 只供规划与事实校验，不等于医生在现场已经知道；未在改写对话前文由患者、陪诊者或医生明确说出的内容，对医生均不可见。

### 成对互动档案（先配对，再选人设库标签）

不要分别随机一个医生人设和一个患者人设。先生成 `interaction_profile`，再从人设库选与之相容的标签。双方职责必须匹配：

| 搭配 | 医生侧 | 患者侧 |
| --- | --- | --- |
| 患者话短、需追问 | 更多复述确认、主动组织话题；`doctor_echo_mode=high` 合理 | 短答，等问再补；`patient_echo_mode` 通常 `low` |
| 患者表达欲强、会补细节 | 少复述，多用开放问题和简短回应；`doctor_echo_mode=low` | 叙事、answer_then_add；可半句接住医生刚说的词再补充 |
| 患者焦虑、反复确认 | 更常安抚、总结；不新增无来源预后 | 可重复追问已许可关切；`patient_echo_mode=high` 合理（复述医嘱/诊断名再问） |
| 医生偏细致解释 | 拆语义组，勿一轮科普 | 适量「嗯、好、我明白」，以及针对**已说内容**的短问或半句 echo |
| 医生偏效率 | 问答更短；`doctor_echo_mode` 不宜虚高 | 不要强行连续热情回应或长解释 |

echo 是**双方**的接话手段，不是医生专属。`doctor_echo_mode` 与 `patient_echo_mode` 只描述各自倾向，**不是硬性频率限制**，也不要对某一方设全局预算。`doctor_echo_mode=high` 表示「碎信息时半句确认再推进」，**不是**每条 fact 先整句 echo 再停。高频复述在匹配职责时合格：医生确认碎信息后立刻追问；患者核对刚听到的医嘱、诊断名或检查名后再问已许可关切。

每次 echo 必须推进或被接应，不能空转复述，也不能双方每轮把对方整句重复一遍（禁止 echo 乒乓球）。默认只复述 **2–6 个汉字**的关键片段，禁止整句回读，禁止「你是问能不能做」「你担心要一直压着」这类元复述或整句重说。`echo_confirm` 不得单独占一轮后停住：字数够则同轮接上问/答/建议（半句 echo 不算第二条命题，合计仍 ≤ 二十）；否则**紧接着自己的下一轮**必须推进。对方可用 `嗯` / `对` 接住 echo，但不能整段只互相复述。禁止把每条 fact 做成独立「陈述—整句 echo」对。

```text
interaction_profile:
  patient_style: concise | narrative | anxious | hesitant
  doctor_style: efficient | confirmatory | explanatory | supportive
  rapport: neutral | friendly
  doctor_echo_mode: low | normal | high
  patient_echo_mode: low | normal | high
  patient_initiative: low | medium | high
```

人设库标签必须能从这个档案派生，不能档案写 concise+efficient，却让医生大段宣教、患者热情追问。派生对照（可组合，不是唯一解）：

| 档案字段 | 更相容的库标签 |
| --- | --- |
| `patient_style=concise` | `taciturn_minimal`、`elderly_slow_recall` |
| `patient_style=narrative` | `chronic_self_manager`、`anxious_overexplainer`、`researched_layperson` |
| `patient_style=anxious` | `anxious_overexplainer`；医生侧偏 `gentle_reassurer` / `supportive` |
| `patient_style=hesitant` | `little_medical_knowledge`、`elderly_slow_recall` |
| `doctor_style=efficient` | `high_volume_rushed`、`checklist_outpatient`、`senior_authoritative` |
| `doctor_style=confirmatory` | `ordinary_outpatient_style`、`tired_but_careful` |
| `doctor_style=explanatory` | `teaching_explainer`、`early_career` |
| `doctor_style=supportive` | `gentle_reassurer` |
| `doctor_echo_mode=high` | 医生 HABITS 写「半句确认后追问」；勿每条 fact 先整句 echo 再停，勿与 `efficient` 强行叠成连讲 |
| `patient_echo_mode=high` | `anxious_overexplainer`、`researched_layperson`、`medical_worker_or_student`、`follow_up_regular` |
| `patient_echo_mode=low` | `taciturn_minimal`；短答即可，不必复述医生原话 |

### 主规则：医学命题等价（不是词义相近）

医学表述只能做**语义等价**改写，不得做医学推断、概括、扩展、弱化或强化。可换自然说法、拆分或合并、改信息顺序与句法；每个医学命题本身必须无损。

「完全等价」= **医学命题等价**。只要下列任一维改变，即使句子看起来差不多，也不算等价：

```text
主体：谁的情况
内容：症状 / 诊断 / 药物 / 建议 / 风险（及具体对象）
时间：既往 / 当前 / 持续 / 某时点
极性：有 / 无；肯定 / 否定
程度与数量：偶尔、经常、全部、一次、阈值等
模态：可能、可以、建议、需要、必须
依托：在什么情境/条件/基线下成立（depends_on + setting）
范围：一般医学说明，还是对该患者的判断
信息来源：患者自述、检查结果、医生判断、医生建议
```

这 9 维接到现有 `FACT_BINDINGS`（主体=`owner`/`entity`，内容=`attribute`+`value`，时间=`tense`/`temporal_scope`，极性=`status`，程度=`degree|severity|frequency`，模态=`modality`，依托=`depends_on`+`setting`，范围=`scope`/`source_type` 族，来源=`provenance`/`source_type`）。换绑任一维即偏移。`status` 只表极性，不再用 `status=条件` 兼管「何时成立」。

### 依托关系（陈述文与 fact 并行）

原子 fact 会把「B 只在 A 的情境下成立」削成无依托的全称命题。这是一类问题，不限于否认：

- 发作期/情境否认 → 平时/一向没有（咳嗽时胸口疼 → 平时胸口疼）
- 只在某动作/时间成立的症状 → 持续存在（蹲下才晕 → 老是晕）
- 相对基线的变化 → 绝对状态（比上周轻 → 很轻）
- 条件性建议/触发 → 确定结论（任一项出现即就医 → 严重了再去）
- 检查/转述来源 → 本人病史（检查说是某病 → 以前得过）
- 问 A 的答案接到无关 B

Stage 1 **并行**写 `SOURCE_DIGEST` 与 `LOCKED_FACTS`，两路都对**原始台词**，不是先压陈述再切 fact。陈述文保住原话与依赖；fact 从原文填并带 `quote=`（一组能完整表达该命题的原文子串，用 `+` 连接）。后段两路都读：fact 管覆盖与许可证，陈述文管依赖不得削平。一边有依托另一边没有 → Contract 失败。

说出或激活带 `depends_on` 的 fact 时，被依赖 fact 必须已在 `ACTIVATED`，且其关键内容词已在**本轮或相邻轮**的 `SURFACE`。否则依托丢失，听成全称/平时/绝对状态。不强制同一轮说完。

分层从许可证推导，不另写 `layer` 字段：

```text
medical_content:
  有 supports / activates，或台词含可记录的医学、行为、身份、计划断言
  必须医学命题等价（双向蕴含，且不得额外蕴含新命题）

conversational_surface:
  pure_backchannel / acknowledgement / request_continue / closure
  且不引入新命题
  可自然变化（嗯、好、我明白了、您继续说）
```

`嗯` `好` `我明白了` `您继续说` `这个我听懂了` `哦，反流啊` 可以自由变化；后一种只准用对方刚出口的词。`我烟酒都少碰` `我会按时去做` `我以前停过工` 不可以，因为它们已是新的可记录事实。表面层失败即偷渡 `medical_content`。

### 命题预算与对话可见性

最终对话中的每一条可被记录为事实、状态、意图、行动、评价或承诺的内容，必须可回溯到 Contract 中的一条 `fact_xx`，且与该 fact **医学命题等价**。

Contract 只供规划与校验。现场医生没有剧本。Stage 2 起维护（最终 JSON 不输出）：

```text
CONVERSATION_STATE:
  ACTIVATED: 已在当前改写对话中明确说出的 fact_id
  SURFACE: 这些 fact 被说出时实际出口的内容词（对象、药名、检查名、时长等）
  PATIENT_PRIVATE: `owner=患者|陪诊者` 且尚未说出的事实
  SOURCE_ONLY: `owner=医生` 且尚未说出的事实
```

激活同时记 **fact_id** 与 **已说出口的内容词**。`knowledge_basis=shared` 只能用当时 `SURFACE` 里出现过的词，不能因为 fact_id 已激活就补全省略对象。患者说「做过三周」只把「三周」写入 `SURFACE`；医生不得补出「牵引」，除非前文台词已出现该对象。

说出或激活带 `depends_on` 的 fact 时，被依赖 fact 必须已在 `ACTIVATED`，且其关键内容词已在**本轮或相邻轮** `SURFACE`。后段同时读 `SOURCE_DIGEST`：fact 管覆盖，陈述文管依托不得削平。

所有权与首次激活：

| 类别 | 谁可先说出口 |
| --- | --- |
| `owner=患者` / `owner=陪诊者` 的症状、否认、病史、检查史、用药、担忧、核心问题 | 必须患者或陪诊者先说；医生只能用事实盲问题引出，不能自己 `present_fact` 或 `activates` |
| `owner=医生` 的诊断、解释、医嘱、条件风险提示 | 医生可首次说出，但须已有相关病情前件，且不能当开场第一句 |
| 仅源文本、双方都未说 | 谁都不能当共享病历引用 |

医生给自己的建议 ≠ 替患者把「我想问胃镜」说出来。

硬规则：

1. 医生不得把 `patient_private_facts` 或未激活的患者来源事实当已知前提：不得点名其主题、症状、检查、治疗、担忧，或用候选答案、方向、时间锚点、程度、因果、否定、诊断名、治疗名暗示答案。医生首轮只能中性接诊或事实盲开放问题，如「今天哪里不舒服？」「这次主要想问什么？」。点名「关于胃镜你想问什么」不算中性。
2. 患者首要诉求必须先由患者表达，医生才能进入该主题。患者可开头说全，也可先报病名再补问题；医生不得抢先。
3. 医生首次说出 `owner=医生` 的 `source_only_facts` 合法，但只可用作自己的诊断、解释、医嘱或条件性风险提示，且须在相关病情前件已激活后以 `knowledge_basis=doctor_statement` 激活该 fact。禁止把这项例外用来替患者陈述未说出的关切，或把患者来源事实说成医生已知。
4. 有依托的命题不得说成无依托全称。被依赖内容词须在本轮或相邻轮可听见；不强制同一轮说完，也不得隔开后只剩「平时没有 / 一直如此 / 很重 / 严重了再去」。

尚未激活的患者来源事实只能由患者/陪诊者说出口而激活。医生对未激活目标只能使用**事实盲**开放问，或真正对称且不带前提的选择问；不得含该 fact 的内容词，也不得暗示候选答案、方向、时间、程度、因果、否定或预设答案。`跟之前差不多，还是有变化？` 若既往基线未激活也不合格；可改为「这段时间有什么变化吗？」。不能因为 Contract 里有，就让医生点名主题、复述细节或替患者给针对性关切。禁止「从刚激活的病名联想到患者还没说的关切」。

医生轮须标 `knowledge_basis`：

| 值 | 规则 |
| --- | --- |
| `shared` | 该轮具体对象、症状、担忧、时间必须 ⊆ 当时 `ACTIVATED` 的 fact_id，**且**内容词 ⊆ 当时 `SURFACE`（已说出口的词）。不得补全患者省略的病名、药物、检查、治疗或时间 |
| `neutral_open_question` | 只能事实盲开放问或对称选择问，不能藏入任何尚未说出的具体事实或答案倾向 |
| `doctor_statement` | 医生首次激活自己的诊断、解释、医嘱或条件风险 fact；该 fact 必须 `owner=医生`，相关病情前件已激活，且不能假称患者已有该表现 |

### 受控 Listener Response（响应式过渡轮）

对上一轮有真实反应，并且可选地推进一个已获许可的话题。不要为了每轮交替而制造过渡轮。

对方刚说完一条实质内容、本轮要接话时，**优先带一点已听见的内容**（上一轮已出口的 2–4 字，或 `对` / `哦这样`），再问、答或给下一条。不要只用光秃秃的 `嗯` 就换到无关主题。清单交替、连续第二条建议前，单独 `嗯` / `对` 仍够。不必每轮另开回应轮，也不要整句回读。

| `act` / 形态 | 作用 | 推进新内容 |
| --- | --- | ---: |
| `pure_backchannel` | `嗯` `好` `行` `哦`；清单交替处即可 | 否，完全合法，不必强行补事实 |
| `acknowledgement` | 简短确认理解；可带上一轮 2–4 字已出口词（`哦，反流啊`） | 否 |
| `request_continue` | `嗯，您接着说` | 否；**仅当**计划中确有尚未表达的后续内容 |
| `answer_then_add` | 先答，再补**另一条**已锁定未激活事实 | 是；合计将超约二十字则拆成两轮 |
| `answer_then_ask` | 先答，再问与当前话题有关且已许可的内容 | 是；超字数则答、问分轮 |
| `ack_then_ask` | 先回应解释，再追问已许可关切 | 是；超字数则分轮 |
| `echo_then_probe` | 半句复述刚激活的关键片段后再问 | 问句受激活规则；默认同轮（如 `躺下更明显，多久了？`）；合计将超约二十字才拆，拆后自己下一轮必须接上问句 |
| `partial_answer_then_recall` | 先答一部分，再补相关已锁定信息 | 是；超字数则分轮 |
| `continue_fact` | 被合作打断后由原说话人续完同一许可 fact | 否；不得补入新 fact，须带原行的 supports / activates / knowledge_basis |
| `topic_shift` | 先结束当前问，再切入另一已许可主题 | 是；须半句收住或说明先说另一点，不得把无关 fact 直接当答案 |
| `closure` | 收尾、结束当前话题 | 否；不得借收尾新造医嘱或预后 |

纯回应不能偷偷新增「我会去做」「我记住了以后一定……」类依从承诺。推进内容必须来自尚未表达的锁定事实，且若该事实是患者私有关切，必须等患者先说出口。不得把「原始患者的核心咨询意图」交给医生先开口。

现场功能对照（不另写 `function` 字段，用 `act` + `reacts_to`）：

| 现场功能 | 对应 `act` |
| --- | --- |
| answer | `answer`；`advise` / `present_fact` 仅当 `reacts_to` 是患者问句且该 fact 能答该问 |
| follow_up_question | `open_probe` / `detail_probe` / `echo_then_probe` |
| acknowledgement | `pure_backchannel` / `acknowledgement` |
| safety_reminder | `warn` |
| topic_shift | `topic_shift` |
| closure | `closure` |

上一轮是患者问题（`status=疑问` 或问号）时，下一位医生的**首个实质轮**必须：回答、澄清、为回答所必需的追问，或显式 `topic_shift`。`advise` / `present_fact` 若不能答该问，不得直接当答案，须先 `answer` / 澄清或 `topic_shift`。`topic_shift` 须先结束当前问（半句收住或说明先说另一点），再切入风险/建议/检查。禁止把同段原文里无直接问答关系的锁定事实接成答案。`reacts_to` 指向被回答/被接住的上一问；无问答关系写 `none`，且不得假装在答。

### 问题模式（不能未卜先知）

每个问题必须声明 `question_mode`：

| 模式 | 目标事实状态 | 规则 |
| --- | --- | --- |
| `open_probe` | 未激活 | 不预设答案 |
| `neutral_choice` | 未激活 | 给对称选项，不暗示其中一项为真 |
| `echo_confirm` | 已激活 | 只复述 2–6 字关键片段；不得整句回读或元复述；不得单独占一轮后停住，须同轮或自己下一轮推进 |
| `detail_probe` | 已激活 | 只展开已出现事实的维度 |

硬规则：问句中的事实性前提必须已在 `activated_facts` 中。未激活：`这几天情况有什么变化吗？` 合格；已激活「昨天加重」后才可 `加重以后还吐过吗？`。禁止把答案塞进问题，也禁止把**未说出的主题词**塞进问题：患者未提「胃镜」前不得问「关于胃镜你想问什么」。`echo_confirm` 与 `detail_probe` 只能引用已激活事实。`echo_confirm` 后若自己下一轮既不推进、对方也不接应，视为空转失败。

### 语义组、压力与打断（字数优先于「一组说完」）

一轮默认只承载 **一条** 实质命题：一个问题，或一个短答，或一条建议，或一个征象，或一种药名，或一个解释结论。半句 echo（2–6 字）不算第二条命题，允许短轮里叠「半句 echo + 推进」（仍 ≤ 二十）。仅当两句是同一人对**同一 atomic fact**不可自然拆开的「回答 + 极短限定」时，才可双命题，且两句不得分别有独立 `fact_xx`、不同时间/来源/极性，也不得属于 `complete_set`。征象清单、忌口清单、多药名、住院步骤**禁止**因「同属一个风险类别/建议组」而压进一轮。每条一轮，或半句后听者 `嗯` 再下一条。药名可切开（如先两种、再两种），但最终名称与种类必须正确、不得漏药。`complete_set` 仍须全员说出，用交替而不是连发；禁止再收成「注意生活」。

`semantic_groups` **只能为 1**。`pressure=high` 只表示「后面还要拆、不要本轮写长」，不是许可证。不能把整段科普压成一轮只塞「呃」。失流不能替代语义拆分。字数规则见下节，与语义组冲突时以字数为准。

相邻轮次优先交替，不为交替制造 bridge。**同一人连续实质轮最多 2**：建议、药名、征象、解释结论、新事实都算实质轮。第 3 条实质内容前必须插入对方短回应或半句接话（`嗯` / `对` / 短问均可）。纯 backchannel 不算实质轮。`request_continue` 仅当后续确有未表达计划内容。

打断低频、友善、合作，不要每段都有。只打断意图引子或连接词；不得切在药名、剂量、时间、否定、诊断、风险条件中间。被打断信息必须恢复。短对话通常最多一次。

`interruption`：`none` / `starts_interrupted` / `interrupts_previous`。`interruption_type`：`overlap_backchannel` / `cooperative_preemption` / `clarification_interrupt` / `completion_interrupt`。

**禁止默认补全场景。** 无 fact 不得出现病历、报告、家长/陪诊。中性「这次主要想问什么」允许；点名主题的「关于胃镜你想问什么」禁止。不要用点名套话逼患者把线上标题再背一遍。

### 原子事实与必须整组保留的集合

锁定事实分两类：

```text
atomic_fact: 可单独重排、分轮说出
complete_set: 必须整体保留的枚举/条件集合
```

`complete_set` 适用于：多种药物的完整清单；多条生活建议；风险信号列表；「任一项出现即就医」之类触发条件；带数值阈值的条件；并列检查结果或并列否认项。

可以分多个 turn 表达，**不得摘要、抽样保留或遗漏任一成员**。所有成员都 `activates` 之后，才能判定该组已覆盖。触发条件不得因列表被压缩而变弱。禁止把完整风险清单收成「眼睛黄、尿也黄」一类抽样句。

年龄：仅当**原始 dialogue 台词**明说了年龄，才锁成 `fact_xx`（`owner=患者`），并由患者或陪诊者在对话中途带出。仅出现在 `meta` 的年龄不锁、不进 `REQUIRED_FACTS`、对话中不说。不得单独开场自报年龄。医生不得追问、念出或确认年龄。性别永不点名、永不索要、不锁成 fact、不进 `REQUIRED_FACTS`；医生不得问「年龄和性别」，对话里不得出现「男性 / 女性」等性别词。

### 认识来源与适用范围（`source_type`）

不得改写事实的认识来源或适用范围。细目短词保留；跨**族**改写即失败。

| 族（只读分组，不另写字段） | 目录细目 |
| --- | --- |
| `patient_report` | `patient_report`（患者自述症状/否认/经历）；`past_diagnosis_as_history` |
| `test_or_diagnosis_result` | `exam_result` |
| `doctor_general_statement` | `general_statement` |
| `doctor_patient_specific_assessment` | `individual_attribution`；`definite_conclusion` |
| `recommendation` | `conditional_advice`；以及 `modality=建议\|必须\|按原处方` 的医嘱 |

- 既往**检查结果/诊断报告**不得改成「以前得过某病」的病史独白（跨 `test_or_diagnosis_result` → `patient_report`）。
- **一般医学说明**（「这类药会有这种副反应」）不得改成对该患者此刻的个体归因（「这可能就是药引起的」）。
- 条件性建议、许可医嘱不得改成确定结论。
- 具体治疗对象不得上位泛化：`三周牵引` 不得写成 `三周治疗`。
- `unspecified_source` 只能留在未说明，不得升级进任何一族。
- 自定义 id 的 gloss 必须写明所属族，且不得借 gloss 跳族。

改写必须**医学命题等价**（上节 9 维同锁）。词义相近不算等价。不得推断、概括、扩展、弱化或强化。`某病毒` 不得写成 `某病毒等病毒`；`任一项出现即就医` 不得写成 `出现严重表现再就医`。

若原文先把某状态当未实现目标、后文患者已具备该状态，重组时**必须先激活当前状态**，后续预后只谈「在现有基础上还能改善」，禁止再把已实现状态当目标。这是保真重组，不是新造事实。

### Contract 属性目录与自定义（`CUSTOM_VOCAB`）

Clinical Contract 的 `source_type`、`FACT_SETS.kind`、`status`、`provenance`、`modality`，以及 bindings 上的 `tense` / `relation`，**优先用下面的目录短词**。目录能保真时禁止另造。`owner` 是封闭字段，只能为 `患者` / `医生` / `陪诊者` / `未说明`，不得自定义。

目录短词本身已带解释（与人设库同构：标签 + 落地说明 + 禁区）。自定义必须写成同一形态：短 `id` **加上**完整 `gloss`。禁止只丢一个新单词（如 `source_type=hearsay`）。

目录能覆盖则不要写 `CUSTOM_VOCAB`。对不上时在 Stage 1 登记：

```text
CUSTOM_VOCAB:
- field=source_type | id=family_relayed_exam | gloss=家属转述的既往检查结论，不是患者本人「得过该病」，也不是医生当场新诊断
```

`id` 可用英文下划线；单独一个 id 不算完成。`gloss` 须说明：这个值是什么、对话里应如何说出、所属 `source_type` 族（若 `field=source_type`）、**不能**借它改成相邻更强的目录项或跳族。Bindings / `FACT_SETS` 只引用目录短词或已登记的、`field` 与引用字段完全一致的 `id`。自定义不得升级强度、不得跨族（检查结果仍不得变成病史）。`kind` 即使自定义，该组仍是 `complete_set`，必须全员覆盖、不得抽样。后续 stage 执行 `gloss`，不得把自定义标签压成空话。无自定义时写 `- none`。

### 状态与关系漂移

9 维必须医学命题等价。不得改变：

- **时态**：不得把「正在治疗」改成「之前得过、已经过去」。
- **极性 / 程度**：完全否定不得改成部分否定（「没吃」≠「吃得不多」）；频率、数量、阈值不得改约数。
- **模态**：不得把「可以查」改成「建议你去查 / 可以查一下看看」；不得把「如果可以的话到……」改成「我建议你去……」；不得把一般说明改成针对该患者的明确因果。
- **关系**：无依据不得改成「家长」「我家孩子」「陪诊」。
- **时间绑定**：不得把「做过两个月理疗」加成「刚得病那会儿做过」。
- **状态矛盾**：已说能生活自理，不得再把「恢复到生活自理」当未实现目标。原文若先预后后补充已自理，改写须先激活已自理，预后改为「还能在现有基础上改善」。原文内冲突时优先保留明确、具体、当前时态的患者陈述；其它改为「在现有基础上继续改善」或重排，不得新造矛盾。
- **覆盖遗漏**：拆分重排后丢掉病情变化、风险条件、`complete_set` 任一成员或患者核心提问。组未说完不得标 covered。
- **认识来源**：检查结果 ≠ 患过某病；类药一般说明 ≠ 个体归因；不得跨 `source_type` 族。
- **错误强化**：无原文强调时不要用「这点一定要记住」。
- **记忆状态**：原文未说「记不清 / 说不准」时不得添加，也不得据此把未表态的项目当成「没做过」。
- **阈值改写**：`六小时以上无尿` 不得改成「六个多小时」；约数只能沿用原文约数。
- **抽象层级 / 命题扩展**：口语同义必须仍双向蕴含。禁止降一层展开、加「等」、弱化阈值或强化模态。抽象 fact 只能停在同一抽象层级，除非原文已给出该成员。「能独立走路」≠ 自己买菜做饭；「已上班」≠ 停工后复工；「未进食」≠「吃得很少」；「某病毒」≠「某病毒等病毒」；「任一项出现即就医」≠「出现严重表现再就医」。不得把医生建议改成患者既往行为、依从承诺或生活习惯。

患者极少怀疑医生。对话尽量保持友好。

### 单轮字数与标点（强制，各 stage 均须遵守）

对最终 `text` 和 Spoken Base 台词计数（不含说话人标签、不含中间许可证字段）：

- **优先 ≤ 二十个汉字**。
- **含失流硬上限四十个汉字**。超四十必须拆轮，不能靠 `呃` `……` 顶住。
- echo 半句加追问、两条建议、答加补充：合计将超过约二十字就拆成两轮。
- 不要用「目前就这些」断言没有别的症状。

台词禁止书面列举标点：

- **不得出现 `：` 或 `；`**（这不是演讲稿，也不是病历）。坏：`看这些表现：眼睛黄，尿也黄……`。改成问句或拆轮，如 `看眼睛黄不黄。` / `尿黄吗？`
- 顿号 `、` 只用于该轮仍 ≤ 二十的自然并列。四种药宁可两轮各说两种。
- 台词不用阿拉伯数字（药名/检查名原文如此者除外）。年龄仅在已锁定为 fact 时由患者/陪诊者带出，且不得单独开场自报；医生不得问年龄、不得念 `meta` 年龄。对话中不得出现「年龄和性别」「男性」「女性」等点名。时长说「六个小时以上」。`meta.age` 仍用整数。

### 绝不允许的事

- **不新增患者病例细节**：不能补症状、病程、诱因、检查结果、既往史、用药史、过敏史、孕育状态或疗效。也不能为了让医生能问诊而让患者凭空回答。
- 不新增、不替换、不夸大医学结论、诊断、检查、药物、剂量、治疗、风险、注意事项或安慰性判断。
- 不把「没有、偶尔、考虑、可以、不一定、问是否」说成相反、更重、更频繁、确诊或必须；也不把「可以」说成「建议你必须去」或「可以查一下看看」。
- 最终台词不得含 `：`、`；`，不得把清单写成文书冒号句。
- 不得无来源添加「记不清」「说不大准」。不得让医生点名患者尚未说出的关切主题词。中性开放问「这次主要想问什么」可以。不得点名或索要性别；不得由医生问起年龄；无原始台词依据不得自报年龄。
- `PATIENT_META`、`patient_profile`、仅出现在输入而不在原始台词里的背景，默认不得写入最终 `dialogue`。其它 meta 仅当原始台词已说出才可表面化；不得用「医生先问再答」或「医学判断需要」重开年龄/性别口子，也不得把未说背景改写成患者主动补充。
- 不得把抽象事实展开成具体成员（能独立走路 ≠ 买菜做饭；已上班 ≠ 停工后复工；没吃 ≠ 吃得不多）。不得把医生建议改成患者自己的既往行为或依从承诺。
- 不得无依据改变时态、治疗是否正在进行、患者/家属关系，或把一件事绑到原文没有的时间点。
- 结尾不得无来源地加重强调（「一定要记住」）。
- **医学事实不是关键词集合，而是有关系的原子命题。** 每条锁定事实同时保护其**主体、实体/对象、属性值、时间归属、信息来源、确定性、极性、频率/程度、范围和语用目的**。重排或换说法可以；将同一个值、限定词或意图挂到不同实体、主体、时间或范围上则不可以。
- **原文未说明的关系必须保持未说明。** 不得把一个事实的时间、来源、对象、状态、力度或范围自行补全、转移、合并、拆分或推断成另一种关系；不得把上位问题/建议/结论替换为其中一个下位选项，或反过来扩大其范围。不得把「B 只在 A 时成立」削成无依托全称（咳嗽时胸口疼 ≠ 平时胸口疼；蹲下才晕 ≠ 老是晕；比上周轻 ≠ 很轻）。
- 不把线上特有内容原样搬到线下：上传、发图、语音/视频、平台、在线、刚看到、在开车准备去医院、到正规医院检查等。若发现类似「开车时头晕」等的内容，属于症状发生背景，则保留其病史意义。
- 咳嗽、笑、吸气、叹气、背景声、重叠语音、括号动作**不是文字失流**，最终 `text` 不得出现。
- 最终 JSON 不得包含 `clinical_contract`、`spoken_base`、`disfluency_plan`、`TURN_PLAN` 或任何中间计划字段。

事实点怎么数：一种症状、一种药物、一种治疗/护理、一条生活建议、一项检查、一个诊断名、**一个**风险征象各算一个。黄疸征象、生活限制、多药必须拆条并收入 `complete_set`，不得收成一条、也不得抽样摘要。Stage 5 不得把已拆开的事实重新合并成宣教稿。患者核心问（如某病是否更严重）不得当可删解释。

## 中间格式 vs 最终格式

Stage 0、Stage 5、Stage 6 输出 **一个 JSON object**。Stage 1–4 输出 **受控行式文本区块**（不是随意散文，也不是 JSON）。不要 Markdown 解释、不要把最终 JSON 提前写出来。

行式区块用固定起止标签。字段名大写。列表用 `- ` 开头。`TURN_PLAN` / `SPOKEN_BASE` / `DISFLUENCY_PLAN` 一行一个单元。不确定时写 `none` 或省略该条列表项，不要填「未知」。中间计划可写 `AVAILABLE_FACTS` / `FACT_SETS` / `CUSTOM_VOCAB` / `CONVERSATION_STATE` / `knowledge_basis` / `activated=` 等字段；最终 JSON 不保留它们。

最终 `text` 不用阿拉伯数字、英文字符（药名/检查名原文如此者除外）、`：`、`；`、括号动作或线上平台词。数字改为自然中文说法。`meta.sex` 为 `男` / `女` / `null`；`meta.language` 为 `Chinese` / `null`。

## 人设来源库：必须从这里选择或按同款格式自创

人设描述互动方式、说话节奏、知识表达方式和口头习惯，**不能**新增情绪事实、职业事实、疾病事实或诊疗结论。标签从 `interaction_profile` 派生后再到本库选择或组合，禁止两边独立抽签。标签可以 `|` 分割。可以只作为幕后习惯。

无论何种组合：最终医学含义必须落在 Clinical Contract 的 `LOCKED_FACTS` 上。双方 echo 多少由 `doctor_echo_mode` / `patient_echo_mode` 与当场功能决定，不设全场配额。

### 患者

- `chronic_self_manager`：长期和同一类问题打交道，有一点自我管理语言；可以更快抓住「减量、复发、忌口、检查」这类契约里已有的词，但仍可能把句子说断、问得很生活化。
- `medical_worker_or_student`：懂得一些术语，记忆不清晰，可能用诊断名/检查名反问，或先说半句术语又换成日常词。**不能**因此补出契约没有的诊断、检查、疗法或同事意见。
- `researched_layperson`：可用半懂不懂的口吻追问**契约里已有的**担心或检查名；常半句 echo 医生刚给出的检查名/忌口词再问。不得引进原文没有的网传方案、药名或疗法。
- `little_medical_knowledge`：更多用「这毛病、堵得慌、咋回事」一类日常表达，医生需要把已有结论拆短解释；不是把患者写成低智，也不是强行结巴。
- `elderly_slow_recall`：节奏偏慢、句子偏短；不得添加「我记不太准」一类记忆状态，除非 Contract 已有对应事实。时长可以说不准再立刻改回锁定值，不能把错误时长留作最终事实。
- `taciturn_minimal`：对应 `patient_style=concise`、常配 `patient_echo_mode=low`；能短则短，医生多问才补一句。此时**医生**半句确认后再追问合理，患者不必复述。
- `anxious_overexplainer`：一件事会绕着说、尾部补充；`patient_echo_mode=high` 时可先复述医生刚说的医嘱/诊断再追问。只能重复契约已有信息，不能越说越出新症状。
- `follow_up_regular`：复诊熟客，开口容易对上药/复查/旧诊断（仅当契约已有复诊线索），少寒暄；可 echo 医生刚点到的旧药名再问。
- `dialect_colloquial`：更易出现句尾焦点、倒装、生活词；书面仍按样本主语言写，**不要**先写普通话再机械翻译成粤语/英语。
- `parent_proxy`：仅当原文已是家长代述患儿时选用；陪诊/代述者放 `COMPANION`，不要无中生有一个家长。

### 医生

- `very_familiar`：用语利落，但也可以有简短 echo、俚语、倒装和轻微嘴飘。
- `ordinary_outpatient_style`：常见门诊表达，边问边接话；在 confirmatory / `doctor_echo_mode=high` 时更常半句复述，在 narrative 患者下应少复述。
- `tired_but_careful`：有「嗯、这个、是吧」、短暂停顿；医学专名可轻重启，但最终必须落回正确名称，不能表现为粗暴、漏诊或乱开药。
- `less_familiar_with_topic`：可用更短、更生活的已有说法，术语可说到一半再补全；不能因「不熟」虚构模糊诊断，也不能把错误术语留作最终信息。
- `early_career`：解释会略显按步骤、偶尔重复连接词，但不必写成书面教学。
- `high_volume_rushed`：话短、一次一事、收尾快，对应 `doctor_style=efficient`；不要强行连续解释和热情回应，但仍把锁定医嘱说全。
- `teaching_explainer`：把已有结论拆成两小句，偶有连接词重复；禁止借讲解补充新机制/新检查。
- `senior_authoritative`：判断干脆，少铺垫；允许轻微口癖，禁止唬人式新诊断。
- `gentle_reassurer`：先接住担心再给已有结论，不新增安慰性预后（如「肯定没事」「一周必好」）。
- `checklist_outpatient`：习惯按主诉—否认项—解释—医嘱推进，问句偏短。

### 自定义

- `other: 一个自定义的更好的人设描述句子`：允许自创符合真实门诊的人设，只要后续 stage 能执行。写法参照上面预设：点明知识表达方式、节奏、一两类口头习惯，并写清**不能**借此人设新增的东西。

### 人设如何落到字面上（必须可听见，不是标签装饰）

同一临床素材可以走完全不同的表面路径。例如同样是「可以做胃镜、未做过、不是必须手术」：慢病自我管理者可以先问「那是不是得一直压着吃」；医学生式患者可能先说「胃镜那个没做过，能补吗」；患者激活「未做过」后，疲惫但谨慎的医生才可说「没做过是吧？胃镜能做的」。三种都不能增加检查种类、反酸频率或治疗方案。

`signature` 习惯要具体到**可观察的接话方式**，例如「半句确认后追问：`躺下更明显，多久了？`」「短答再补」「先答再问：`药按说明吃。那能做吗？`」「担心时把关键词放句尾：`要一直压着吗这个？`」「药名或术语说到一半会补全」「常用`这个、哈、是吧`做承接」。不要只写「自然、焦虑、耐心、口语化」。Stage 2 的 `HABITS` 每名角色至少一条必须是这种接话方式，不能只写态度词。习惯可以碰锚点，但最终医学含义必须回到 `fact_xx`。

## 口语现象：倒装、卡顿、口误、修正（解释，不是配额表演）

真实自发语音里的停顿、重复、自修正不是纯随机噪声，而受说话者、上下文和任务影响（Switchboard / Shriberg）。本项目里它们必须**可被 TTS 读出**；最终 ASR 标签必须与读出文本一致。计划了却实现不了的 `嗯……` 或重复，不能留在最终 JSON 里。

### 自我修正的三段结构

```text
reparandum（先说错/放弃部分）
+ interregnum（可选修正提示）
+ repair（最终正确表达）
```

结构示意（医学锚点可以作 reparandum，但同一轮必须修回锁定表达）：

```text
吃了甲硝坐，啊不，甲硝唑。
```

`甲硝坐` 是 reparandum；`啊不` 是 interregnum；`甲硝唑` 是 repair。左边/最终必须是契约锁定的正确表达。

若口误是约定俗成的简称、俗称，或对方一听就能还原成同一实体（如把甲硝唑说成甲硝坐），可以不修正，只要不会被理解成另一种药、另一种剂量或相反命题。

### 倒装与口语句法

这里的「倒装」不是硬套语法教材，而是该语言自然口语语序变化。普通话常见是**焦点后置/话题前置**：`有用吗这个？`、`能做吗胃镜？`、`怎么弄啊现在？`、`这个反酸躺下更明显。` 可参照广东人口语把焦点放句尾的习惯，但样本主语言是普通话时仍写普通话，不要假粤语。英语/粤语仅当 `LANGUAGE` 明确要求时使用各自原生修复方式和语气词，禁止先写普通话再翻译。

允许的口语句法标签：

| 标签 | 含义 | 示例 |
| --- | --- | --- |
| `topic_fronting` | 话题前置 | `这个反酸啊，躺下更明显。` |
| `fragment` | 可由上下文恢复的残句 | `没有，呕过血也没有。` |
| `tail_addition` | 主句后补充限定 | `半个月左右吧，大概。` |
| `natural_inversion` | 该语言自然口语语序变化 | `要一直压着吗这个？` |

「病句」只能来自这些自然口语结构，不是故意写错语法。

### 卡顿与重复

- 词块重复：`就就`、`没……没`、`有有个把星期`。
- 起句重启：先说不完整起句，停顿后回到原句。
- 长解释若有失流，优先落在普通功能词、转折、句间组织处；也可以按「口误与医学锚点」碰术语，但必须当场纠正或属于可理解口误。不得用失流代替语义拆分。
- 高压力轮可用轻微失流，并应伴随拆组或听者回应。
- 回忆时间/药物、补充信息、改话题、被打断后恢复：可有迟疑、重启、自修正。

### 口误与医学锚点

失流**可以**碰到事实 ID 承载的核心实体、数值、时长、药名、检查名等锚点。默认规则是：**先碰到，事后一定要纠正**，使该轮最终命题仍等于对应 `fact_xx`。

可以不纠正的仅限下面几类，且对方必须能完全理解成同一锁定事实：

- 约定俗成的简称、俗称、口语替换（Contract 里的学名与口语指同一物）；
- 音近或词序滑动、听者仍能唯一还原的口误，例如 `甲硝唑` → `甲硝坐`；
- 已由上下文唯一锚定的半截词，随即补全，如 `胃……胃镜`。

仍禁止：

- 把错误时长、剂量、频率、极性、诊断留作最终信息（`十来天` 若不再改回「约两周」，就是改事实）；
- 先说一个**相反**医学命题再含糊带过（坏例：`你必须一直压着，呃不是，也许不用` 若最终仍听不清力度）；
- 医生把错误诊断、药物、剂量或检查结果当作最终信息；
- 用口误引进另一种药、另一种病或新的行动。

### 适用位置（失流规则）

| 情况 | 可用现象 | 不应使用 |
| --- | --- | --- |
| 患者回忆病程、时间、诱因 | 填充词、停顿、短重复、重启、自修正、模糊限定 | 编造病程；把错误时长留作最终事实 |
| 患者描述主观感受 | 残句、话题前置、尾部补充、轻微口语不完整 | 破坏可理解性、补新症状 |
| 患者/医生说药名、诊断、检查 | 半截后补全、可理解口误、立刻自我修正 | 最终仍是另一种药/病/剂量 |
| 医生开放式解释 | 组织性停顿、echo、术语轻重启后还原 | 错误结论不修正 |
| 患者核对已说医嘱/诊断 | 半句 echo 后再问已许可关切 | 借 echo 引入未激活药名、检查或承诺 |
| 医生封闭式提问 | 通常完全流利 | 无意义口头禅/重复 |
| 粤语/广普/英语 | 使用各自原生语气词、句法、修复方式 | 先写普通话再机械翻译 |

硬约束：

- 每轮默认 `0–2` 个失流事件；极短答复 `0–1` 个；医生通常 `0–1` 个。
- 不允许连续多轮人人都有失流；必须有大量自然流利短轮。
- 五个及以上实质轮时，人设习惯仍应可被听见：至少落实 Encounter Plan 中列出的习惯，且至少有一处非纯语气词的口语结构（倒装、词块重复、起句重启、术语检索、省略、残句或话题前置）。这不是「每人固定结巴一次」。
- 医疗锚点的**最终含义**不可被破坏：否认项、药名、剂量、频次、时间、检查、诊断、风险提示。过程中可以碰这些锚点，但除可理解俗称/口误外必须当场纠正。
- 停顿统一实现为 `……`，不要混用 `…`、`(停顿)`。

## 真实转录风格观察库（只学现象，不迁移病情）

```text
医生：没有是吧？当时有没有看呢？
患者：当时没看。
医生：没没看，然后怎么样就好了呢？
患者：休息休息，一下午加一晚上，我请假休息后第二天就好了。
医生：行。呃，最近有再发发吗？
患者：最近就就这段时间，有有个把星期吧。
```

观察：echo、词块重复和嘴飘发生在确认与回忆，分布并不均匀。
```text
患者：就一开始我就是感觉在上班的时候胀痛胀痛的，然后一直冒冷汗，我就……就过来了。
患者：以前有过，但是到到输到那个输尿……输尿管里面就，我去检查，他说可以排出来。
医生：皮皮脂。
患者：就那个什么。
医生：皮脂腺囊肿。
```

观察：较重的卡壳集中在突发经历回忆和词汇检索；术语最终被还原。可学「皮脂 / 皮脂腺囊肿」这种先半截再补全，不要把其中的疾病或检查迁到新病例。短咨询完全不必复制这种密度。

## Few-shot 用法（只训练规则，不训练病种）

不要把评测样本的原句、原实体、原 dialogue_id 放进生成。每条示例只示范一种泛化规则；实体已改写。

**成对人设 vs 独立抽签**  
正：`patient_style=concise` + `patient_echo_mode=low` + `doctor_style=confirmatory` + `doctor_echo_mode=high`，医生半句确认后追问，患者短答不复述。  
反：同一档案却让医生连续热情宣教、患者主动长叙事。  
正：`patient_style=anxious` + `patient_echo_mode=high` + `doctor_echo_mode=normal`，患者复述医嘱/诊断名再追问已许可关切。  
正：`patient_style=narrative` + `doctor_echo_mode=low`，医生少复述、多开放问。  
反：给任一方 echo 设「全场不得超过两次」而对方信息一直碎。  
反：两边都 `high` 时每轮互相整句复读。  
反：HABITS 只写「自然、耐心」，台词里听不见半句确认后追问或短答再补。

**人设接话 vs 文学简写 / 清单导演**  
正：concise 患者短答 `大概半个月了。`，医生 `躺下更明显，多久了？`（半句确认后追问）。  
正：anxious 患者 `药按说明吃。能做吗？`（先答再问）。  
反：每条 fact 做成「陈述—整句 echo」对，如 `反流。` / `你担心要一直压着。` 后无下文。  
反：把门诊写成文学简写：一人长段切开、对方不对 echo 做任何反应。

**echo 有功能 vs 空转复述**  
正（半句 echo + 推进，同轮）：患者说「躺下烧心」→ 医生 `躺下更明显，多久了？`  
正（接住再推进，不必另开一轮）：患者 `大概半个月了。` → 医生 `半个月了，还有呢？`  
正（echo 被接应）：医生 `躺下更明显。` → 患者 `对。` → 医生再问或给下一条。  
正（听懂诊断）：医生 `听着像反流。` → 患者 `哦，反流啊。`  
正（患者，字数够才合并）：医生说「药按说明吃」→ 患者 `按说明吃。能做吗？`  
反：整句 `你担心要一直压着。` 后无问、无建议、对方也不接。  
反：`反流。` / `你是问能不能做。` 这类整句或元复述后换下一条 fact。  
反：`躺下更明显。解黑便这种情况有过吗？` 挤成一轮超二十字仍不拆。  
反：患者 echo 医生尚未说过、也未激活的检查名。  
反：两边对打整句复读。

**request_continue 时机**  
正：医生后面还有一条风险提示，患者 `嗯，您接着说。`  
反：医嘱已经说完，患者仍说「您接着说」；或医生并无下文。

**语义组 / 字数**  
正：生活建议一条一轮，`咖啡先少喝。` / 患者 `嗯。` / `宵夜先别吃。`  
正：四种药两轮说完，名称不错不漏。  
正：同一症状的极短限定 `躺下更明显。烧心也更重。` 仅在两句共同描述同一 atomic fact、且不各自对应 fact_id 时可同轮。  
反：一轮里病因+三项忌口+开药。  
反：两条否认、两种药、两个风险征象或任意 `complete_set` 成员共用一个 `supports`。  
反：把黄疸征象收成 `看这些表现：眼睛黄，尿也黄……`（冒号清单且超四十）。  
反：留观、学雾化、回家接着雾压成一轮。

**complete_set 全员 vs 抽样摘要**  
正：风险组每个征象一轮或至多两征象一轮，阈值原句保留，如 `解黑便了。` / `吐咖啡渣。` / `站不住要去急诊。` 组成员全部说出。  
正：患者核心问单独说出，如 `这比普通反酸更严重吗？`  
反：整组收成 `眼睛黄、尿黄就要当心。` 漏掉其余征象和阈值。  
反：把患者「某病是否更重」当可删解释。

**认识来源 / source_type**  
正：`以前检查说是鼻窦炎。`（`exam_result`，族=`test_or_diagnosis_result`）  
反：`以前得过鼻窦炎。`（跨族到 `patient_report`）  
正：`这类药会有这方面的副反应。`（`general_statement`）  
反：`这可能就是药引起的。` / `你这个就是助眠药的副反应。`（跨族到个体归因）  
正：条件性建议保持「如果出现……再……」  
反：改成确定结论「你现在就是……」（`recommendation` → `doctor_patient_specific_assessment`）  
正：患者自述标 `patient_report`，如 `躺下会更明显。`  
反：把医生建议说成患者「我平时已经少喝咖啡了」。

**CUSTOM_VOCAB（目录优先，自定义须带完整解释）**  
正：目录没有「家属转述检查」时登记 `field=source_type | id=family_relayed_exam | gloss=家属转述的既往检查结论，不是患者本人得过该病，也不是医生当场新诊断`，台词说 `家里人说以前检查是鼻窦炎。`  
反：`source_type=hearsay` 且无 gloss。  
反：gloss 只有「转述」一个词。  
反：原文已是检查报告，却另造自定义并把 gloss 写成「得过某病」。

**专名不得泛化**  
正：`牵引做了三周。`  
反：`治疗做了三周。`

**重组消解原文时序矛盾**  
正：患者先说 `我现在已经能独立走路了。` 医生再说 `还能在现有基础上改善。`  
反：医生先说 `先恢复到能独立走路。` 随后患者才说已经能独立走路。  
这是重排，不是新造预后。

**台词标点与数字 / meta 上场**  
正：`看眼睛黄不黄。` `十二小时解不出，要去医院。` 原文台词已出现年龄时，患者在对话中途带出 `四十二了。`  
反：台词出现 `：` 或 `；`。反：`小伙子42岁。` 反：仅 meta 有年龄，医生念出年龄或患者开场自报 `四十二岁`。  
反：医生 `请先说下年龄和性别`；患者答 `男性`。  
反：输入 profile 写「经常熬夜」，原始台词未说，患者主动补 `我经常加班到很晚`。

**医学命题等价 vs 词义相近**  
正：原文「能独立走路」→ `我现在能自己走。`  
反：`自己能买菜做饭。`（额外蕴含新行为）  
正：原文「未进食」→ `还没吃。`  
反：`吃得很少。` / `吃得不多。`（极性/程度改变）  
正：`以前检查说是鼻窦炎。`  
反：`以前得过鼻窦炎。`  
正：`可能跟药有关。`  
反：`就是药物导致的。`  
正：`任一条都去急诊。`  
反：`严重了再去急诊。`  
正：`这个病毒引起的。`  
反：`这个病毒等病毒引起的。`  
反：医生建议「少喝咖啡」被患者说成 `我平时已经少喝咖啡了` 或 `那我以后一定忌着`。  
反：表面轮说 `我烟酒都少碰` / `我会按时去做` / `我以前停过工`。

**依托不得削平（陈述文与 fact 并行）**  
正：陈述「咳嗽的时候胸口疼」；fact 胸痛带 `depends_on` 咳嗽、`setting=咳嗽发作中`、`quote=咳嗽的时候+胸口疼`（两段都是原文子串，合在一起才完整）。台词在咳嗽已说且相邻点明后才说胸痛。  
反：只摘 `quote=胸口疼`，丢掉「咳嗽的时候」；或收成「平时胸口疼」且 `depends_on=none`；或隔开多轮后只说「胸口疼」。  
正：蹲下才晕 → `quote=蹲下+会晕`，`depends_on` 蹲下、`setting=蹲下时`；邻轮还能听见蹲下。  
反：`quote=会晕` 或台词 `老是晕。`  
正：比上周轻 → `quote=比上周+轻了`，`setting=相对上周`；邻轮有上周/比较基线。  
反：`quote=很轻` 或台词 `很轻。`（丢掉基线）  
正：`quote=要是解黑便+吐咖啡渣+站不住+任一条都去急诊`，触发仍挂在刚说的征象上。  
反：只摘 `quote=任一条都去急诊`，或台词 `严重了再去急诊。`  
正：`quote=以前检查说是+鼻窦炎`  
反：`以前得过鼻窦炎。`  
反：陈述有「咳嗽时胸口疼」、fact 写成无依托症状并推进无依托清单。  
反：把多段原文焊成一句新话当 quote，或先写陈述再从陈述改写 quote。每段必须是原始台词子串。

**无来源套话 / 记忆**  
正：患者按 fact 自报主诉。中性 `这次主要想问什么？`  
反：患者只报病名，医生 `关于胃镜，你想问什么？`  
反：原文没说记不清，却说 `片子拍过没拍过，我还真说不大准。`

**对话可见性 / activated_context_leak**  
正：患者 `我老反酸。` → 医生 `大概多久了？` 或 `这次主要想问什么？` → 患者 `要不要一直压着？` → 医生才说生活限制。  
正：症状已激活后，医生说出 Contract 里**医生名下**的一条生活建议（如 `咖啡先少喝。`）。  
正：患者先说反酸和病程 → 医生以 `doctor_statement` 首次说 `听着像反流。`，不是 `shared`。  
正：患者 `做过三周。` → 医生 `三周了是吧，后来呢？`（只复述已出口的「三周」）  
反：患者 `做过三周。` → 医生 `牵引做了三周？`（补全省略对象；Contract 有牵引不等于 SURFACE 有）  
反：患者未激活病程 → 医生 `昨晚更重了吧？` / `是不是吃药引起的？`；即使写成问号也含候选答案、时间或因果。  
反：患者只报病名 → 医生 `关于胃镜，你想问什么？`  
反：患者未提加重 → 医生 `加重以后吐过吗？`  
反：开场第一句就针对某主题给建议。

**时态 / 模态 / 时间绑定 / 状态矛盾**  
正：Contract「正在吃药」→ 仍说正在吃。  
反：改成「以前吃过，后来停了」。  
正：「可以做胃镜」→ `胃镜能做。`  
反：`可以做一下看看。` / `建议你一定去做。`  
正：「如果可以的话到康复科」→ 保持「可以的话」，不要改成「我建议你住院」。  
反：`我建议到正规康复医院住一次院。`  
正：「做过三周牵引」（无发病时点绑定）→ 只说做过三周。  
反：`刚得病那会儿做过三周牵引。`  
正：已激活「能独立走路」后不再把独立走路当康复目标。原文若先预后后已能走，改写先激活已能走。  
反：后面还说「先恢复到能独立走路」。

**错误强化**  
正：原文有急诊指征才说「站不住要去急诊」。  
反：一般说明后加「这点一定要记住」。

**Listener Response：单纯应答 vs 偷渡命题**  
正：清单第二条前 `嗯。`；医生刚说诊断后 `哦，反流啊。`（只用已出口词）  
正：`嗯，您接着说。` / `好。那还有呢？`  
正：`哦……还有就是……` 随后只补一条已许可且可激活的事实。  
反：患者说完病程，下一轮医生直接换到无关医嘱、无任何接应。  
反：`我后面再安排。` `我会坚持。` `我带了报告。` `我没记清。` `我先去检查。` `我就放心了。`

**回应后推进 vs 无来源关切**  
正：听完已许可的生活限制后问契约里已有的「能不能做胃镜」。  
反：听完后问「那住院到底要解决啥」——Contract 无此关切。

**问答邻接 vs 同段误接**  
正：患者 `要不要一直压着？` → 医生 `不用一直压。`（`reacts_to` 该问，fact 能答）  
正：医生先半句收住再转题：`压着这点先记下。站不住要去急诊。` 拆轮则第一轮 `topic_shift` 收住，第二轮才给风险。  
反：患者问生活限制，医生下一轮直接 `要是解黑便。` 并把风险当该问的答案（同段原文不是问答关系）。  
反：`reacts_to` 写成上一问，台词却在说无关 fact。

**available vs activated**  
正：Contract 有「躺下更明显」，医生先问 `这两天不舒服时有什么变化吗？`（neutral_open_question），患者说完躺下更明显后，医生才说 `躺下更明显，还有呢？`。

反：患者未说「胃镜」，医生 `关于胃镜你想问什么？`

**问题模式**  
正未激活：`这段时间有什么变化吗？`（事实盲 open_probe）。  
正已激活：`昨天更明显，还吐过吗？`  
反：未激活时 `加重了吧？` / `左边最明显吧？`

**合法拆组 + 回应 vs 独白 / 为交替加戏**  
正：医生 `咖啡先少喝。` → 患者 `嗯。` → 医生 `宵夜先别吃。`  
正：同一人连续两条短建议后，第 3 条前对方 `嗯` 或半句接话。  
反：同一人连续第 3 条实质内容无人接话（生活建议、药名、征象、解释均算）。  
反：硬插 `那我一定天天运动`。  
反：把整组收成 `注意生活` 以逃避交替。

**合作式打断 vs 切锚点**  
正：患者 `哦……那我——` / 医生 `先等一下，这一点我还得说完。`（无括号标签；随后补完被打断内容）。  
反：患者说到药名一半被切走且后文不再出现该药。  
反：每段对话都安排一次打断。

**合作性打断 vs 切断锚点**  
正：患者 `哦，那——` 医生 `还有最后一条。` 随后仍说出该条已许可建议。  
反：切在 `甲硝——` 或 `没有解——` 中间；打断后那条风险提示再也没说。

**既往转述 vs 医生翻病历**  
正：患者按 fact 复述「以前查过，说可以排」。  
反：医生 `我看看病历……上面写的是`（无对应 fact）。

**已知诊断 vs 新造当前状态**  
正：只说出已许可诊断名。  
反：`现在没诊断心衰。`

**表层失流 vs 最终损坏锚点**（失流可以碰锚点）  
正：`胃……胃镜能做`；`吃了甲硝坐，啊不，甲硝唑`；听得懂的未修正 `甲硝坐`。  
反：最终只剩 `十来天` 而契约是约两周；最终变成另一种药。

# Stage 0：Meta Inference

仅补全输入 `meta` 中缺失的 `sex`、`age`、`language`。不改写对话，不推断情绪、人设或口语习惯。已有值不改。只有直接证据才推断；证据不足就为 `null`。原始 meta 全空时也必须尝试从首句括注、自称、怀孕/月经等强线索和语种去推导，推不出则 `null`。

## 输入

完整原始记录 JSON。

## 输出

```json
{"sex":null,"age":null,"language":null,"evidence":{"sex":"string","age":"string","language":"string"},"confidence":"low"}
```

`sex` 只能是 `男`、`女` 或 `null`；`age` 只能是非负整数或 `null`；`language` 只能是 `Chinese` 或 `null`；`confidence` 只能是 `high`、`medium` 或 `low`。

## 正例

输入首句含「（男，三十四岁）反酸烧心能做胃镜吗？」，三项均为空：
```json
{"sex":"男","age":34,"language":"Chinese","evidence":{"sex":"首句明示男","age":"首句明示三十四岁","language":"对话为中文"},"confidence":"high"}
```

## 反例

不要因为反流常见于中年男性就猜性别；没有明示就 `null`。不要把「慢性病」映射成焦虑人设。

# Stage 1：Clinical Contract

从原始线上内容抽取**不可改变的医学事实**和**可自由重构的内容**。只抽取，不改写诊疗，不设计台词，不选择人设。后续 stage 默认不再看原文，只看本区块（含 `SOURCE_DIGEST` 与 fact）。例外：Stage 3 / Stage 3 repair 可看紧凑 `[SOURCE_TURNS]`，仅用于补足已许可 fact 提取不准或表达不清，不得当第二病例源。

两路**并行**、都对原始台词，不是「先压陈述再从陈述填 fact」：

1. `SOURCE_DIGEST`：把原文压成更短的陈述文（可多句）。不是病历摘要，不是新对话。必须保留医学原话或同指原词，以及所有依托（情境、条件、比较基线、来源、触发）。禁止丢掉依托后写成全称/平时；禁止把独立事件焊成因果；禁止加入原文没有的背景。
2. `LOCKED_FACTS` / `FACT_BINDINGS`：仍从**原始台词**填。每条 fact 带 `quote=`：列出能**完整表达**该命题的全部原文子串，用 `+` 连接。单段已能完整表达则只写一段；对象、情境、基线、极性、触发散落在不同句时必须全收，禁止只摘 value。每段必须是原始台词子串，不得改写成一句新话，也不得从陈述文抄。陈述文与 fact 必须覆盖同一批医学命题；陈述有依托则对应 fact 必须有 `depends_on` / `setting`，且 `quote` 里也能拼出该依托，反之亦然。

`LOCKED_FACTS` 与 `FACT_BINDINGS` 仍是覆盖与许可证的索引；后段同时用陈述文防止依赖被削平。每条锁定事实必须有稳定 ID：`fact_01`、`fact_02`……后续 `TURN_PLAN`、Spoken Base、Validator 只能引用这些 ID，不能另起短名。

`LOCKED_FACTS` 写成**原子事实**，一行一条，不要大段摘要。覆盖**所有**相关点：主诉、症状、病程、诊断/病情、检查及状态、药物、治疗、自我护理、预防、缓解、忌口、随访、医生解释、患者关切、否定、不确定性。医生给出的生活方式/忌口/复查与药物同等重要。保留极性：偶尔、没查过、可以、不一定、问是否。禁止把「在 A 时 / 相对 A / 因 A」的 B 收成无依托命题，也禁止拆成两条互不引用的 fact。

患者核心问题、担忧、检查史、用药必须写成独立 fact，`FACT_BINDINGS` 标 `owner=患者`、`status=疑问`（若是问句）或相应 provenance。这些在对话里未说出前属于 `patient_private_facts`，医生不得先点名。医生说明/建议标 `owner=医生`。

清单必须拆条，禁止收成一条，并编入 `FACT_SETS`。`kind` 目录（优先用这些；对不上才 `CUSTOM_VOCAB`）：

- `drugs`：多种药物的完整清单，一种药一个 `fact_xx`，同组不得抽样漏药。
- `lifestyle`：多条生活建议或忌口，一条一个，不得收成「注意饮食」一句。
- `risk_signs`：风险征象列表，一个征象一个；时间阈值原文照锁（`六小时以上无尿` 不得改成约数）。
- `triggers`：「任一项出现即就医」等触发条件；可单独成员或组上标 `trigger=`，不得因列表压缩而变弱。
- `denials`：仅收**无依托**的并列否认（`depends_on=none`）。带 `depends_on` 的否认不进该组，避免被清单导演成「平时没有」。不得只留其中一条当作整组已说。
- `thresholds`：带数值阈值的条件集合，阈值不得改约数。

多步骤医嘱逐步拆条；若构成必须整组保留的流程，用目录 `kind` 或自定义 `kind`（须 `gloss`），仍按 `complete_set` 全员覆盖。

`complete_set` 可以分多个 turn，不得摘要、抽样或漏成员。

原文台词明说的年龄锁成独立 fact（`owner=患者`），由患者/陪诊者中途带出，不得单独开场自报。仅 meta 的年龄/性别不锁、不进 `REQUIRED_FACTS`。性别永不锁成 fact。医生不得问年龄或性别。

`FACT_BINDINGS` 是对同一 `fact_xx` 的关系补充。目录能覆盖时用目录短词；对不上才登记 `CUSTOM_VOCAB` 再引用其 `id`。缺失则保持未说明，不得自行升级、也不得用无 gloss 的新单词。

每条具有检查/病史、一般说明/个体归因、条件/确定结论等来源或强度差异的 fact **必须**填写 `source_type`；仅确实不含这些维度的事实才可省略。无法从原文判别时写 `source_type=unspecified_source`，后续不得升级为更强类型。

`source_type` 目录（细目写入 binding；族只用于禁止跨类改写）：

- `patient_report`：患者或代述者自述的症状、否认、病程、经历；不是检查报告，也不是医生判断。族=`patient_report`。
- `exam_result`：既往检查结果或诊断报告上的结论；对话须保留「检查/化验说是……」，不得改成「以前得过」。族=`test_or_diagnosis_result`。
- `past_diagnosis_as_history`：患者当作自身病史说出的既往诊断，不是单次检查报告的转述。族=`patient_report`。
- `general_statement`：类药或一般医学说明（「这类药会有这种反应」），不是对该患者此刻的归因。族=`doctor_general_statement`。
- `individual_attribution`：明确把当前表现归因于该患者正在用的某药/某因。族=`doctor_patient_specific_assessment`。
- `conditional_advice`：条件性建议（如果出现……再……），不是已成立的结论。族=`recommendation`。
- `definite_conclusion`：针对该患者的确定判断或结论。族=`doctor_patient_specific_assessment`。
- `unspecified_source`：原文确有事实但未交代其认识来源或判断强度；保持未说明，不得补成检查结果、既往病史或个体归因。无族，不得升级。

患者自述的症状/否认/经历须标 `patient_report`，不要省略 `source_type`。`modality=建议|必须|按原处方` 的医嘱即使未写 `conditional_advice`，改写时仍按 `recommendation` 族，不得写成确定结论。跨族改写失败。自定义 id 必须在 gloss 写明所属族。

`status` 目录：`肯定` 原文确认如此；`否定` 明确没有/不是；`疑问` 患者或医生在问；`建议` 医嘱性建议；`条件` 该命题本身是条件性医嘱/风险（极性不是简单有无）；`未说明` 极性原文未写清。`status` **只表极性**。何时/在何情境成立用 `setting` + `depends_on`，不要再用 `status=条件` 兼管依托。

`provenance` 目录：`患者自述` 患者或代述者口述；`医生说明` 医生解释/判断；`医生建议` 医生给出的医嘱或处理建议；`既往资料` 旧病历或既往记录（非本次检查报告）；`检查结果` 检查/化验报告；`原文明确` 来源已写清但不必再细分。

`modality` 目录：`可以` 许可、非必须；`建议` 医生建议去做；`必须` 强制/一定要；`如果可以的话` 附加可行性条件的许可；`按原处方` 沿用既有处方的用法，不得强化成必须或添加剂量；`未说明` 力度原文未写。不要把许可写成建议。

`owner` 封闭目录：`患者` / `医生` / `陪诊者` / `未说明`，不得写入 `CUSTOM_VOCAB`。`tense`：`进行中` / `既往` / `未说明`。`relation`：`患者本人` / `代述者` / `未说明`。

格式：

```text
- fact_02 | entity=<实体> | attribute=<属性> | value=<值> | owner=<患者/医生/陪诊者/未说明> | provenance=<目录或 id> | status=<目录或 id> | source_type=<目录或 id；有来源/强度维度时必填> | quote=<原文子串或 子串+子串+…> | depends_on=<fact_id|none> | setting=<情境或 unspecified>
```

`quote` 必填。值为能完整表达该 fact 的全部原文子串，用 `+` 连接（顺序按原文出现先后）。每段都是原始台词子串；拼在一起必须双向蕴含该命题（含对象、依托、极性、触发），不得只摘孤立 value。单段已完整则不加 `+`。禁止把子串改写成新句，禁止从 `SOURCE_DIGEST` 抄。`depends_on` / `setting` 从原文依存抄出（陈述文帮助显式化，不替代原文）；有依托时 `quote` 必须含能点明该依托的原文片段。无依托写 `depends_on=none`、`setting=unspecified`。按需要附加 `temporal_scope`、`modality`、`frequency`、`severity`、`scope`、`intent`、`tense`、`relation`。缺失字段不凭空填写。每条锁定事实是原子**医学命题**：主体、内容、时间、极性、程度与数量、模态、依托、范围、信息来源必须可从 binding 读出或保持未说明；改写时双向蕴含，换绑任一维即偏移。

`FACT_SETS` 格式：`set_01 | type=complete_set | members=fact_a,fact_b,... | kind=<目录或 CUSTOM_VOCAB id>`。`complete_set` 至少含两个原子成员；单一 fact 不得用集合伪装。可附加 `trigger=出现则就医`。无完整集合时写 `- none`。组成员必须同时出现在 `LOCKED_FACTS`。

`CUSTOM_VOCAB` 格式：`field=<source_type|kind|status|provenance|modality|tense|relation> | id=<英文下划线短标签> | gloss=<与目录条目同级的完整解释：含义、如何落地、所属 source_type 族、不得改成哪条相邻目录或跳族>`。每个被引用的 id 必须在此精确登记，`field` 必须和引用字段一致；目录已能保真时写 `- none`。禁止无 `gloss` 的新 slug。

`VISIBILITY_SEED` 必须列出初始场景可见性：所有 `owner=患者|陪诊者` 的 fact 放进 `PATIENT_PRIVATE`，所有 `owner=医生` 的 fact 放进 `SOURCE_ONLY`。`ACTIVATED` 与 `SURFACE` 初始为空。后续 Stage 2 只可在此基础上随 `activates` 转入 `ACTIVATED`，并把实际出口的内容词写入 `SURFACE`；不得把 Contract 当作现场共享病历。

没有 ID 的事实后续一律视为不存在。不要把「患者可能记不清」写进 `FLEXIBLE_FACTS` 来给记忆状态发许可证。

`FLEXIBLE_FACTS` 只写可重排、可换说法、可拆句的东西（问句顺序、句界）。换说法仍须医学命题等价。不得写「患者是否先说得不准」，也不得以可合并为由合并 `LOCKED_FACTS` 或 `complete_set` 成员；时长/剂量的自我修正只可在后续失流 stage 中当场回到锁定值。`FORBIDDEN` 写死不能新造的症状、药、检查、诊断、剂量或医学断言，以及加「等」、弱化阈值、建议变依从。

`LANGUAGE` 写样本主语言代码，如 `zh-CN`；允许后续必要 code-switch，但不改总体语言。`PATIENT_META` 只保留输入 meta 中的年龄、性别等；它仅用于最终 JSON，**不是现场对话知识**。`patient_profile` 与任何仅出现在输入、未出现在原始台词里的背景，同样不得写入对话，也不得改写成患者主动补充。年龄/性别维持硬禁令：不点名性别、不索要年龄、无台词依据不自报；不得用「医生先问再答」或「医学判断需要」重开口子。其它 meta 仅当原始台词已说出才可表面化。meta 仍缺失则写已能确定的部分，其余不要编。`SETTING` 写成线下门诊及可从原文看出的科室/场景；看不出科室就写 `offline outpatient`，不要猜一个专科。

# Stage 2：Encounter Plan

只根据 Clinical Contract 导演一场新的线下面诊。不要写完整台词。规定谁在什么时点为了什么说话，并选定人设。用 `TURN_PLAN` 控制互动与激活，不要用无来源的 FLOW 散文。

## 规则

- 先写 `INTERACTION_PROFILE`，再选与之相容的人设库标签；禁止两边独立随机。`doctor_echo_mode` 与 `patient_echo_mode` 都不是次数上限。格式：`patient_style=… | doctor_style=… | rapport=… | doctor_echo_mode=… | patient_echo_mode=… | patient_initiative=…`
- 开头从 Contract 的 `VISIBILITY_SEED` 抄写 `CONVERSATION_STATE`：`ACTIVATED` / `SURFACE` 初始为 none；`PATIENT_PRIVATE` / `SOURCE_ONLY` 不得自行重分。每轮 `activates` 之后把 ID 挪到 `ACTIVATED`，并把该轮实际出口的内容词写入 `SURFACE`。
- 每条**医生**计划行必须有 `knowledge_basis=shared`、`neutral_open_question` 或 `doctor_statement`。`shared` 的内容词 ⊆ 当时 `SURFACE`（已说出口的词），不是只看 fact_id；`neutral_open_question` 只能用事实盲问句；`doctor_statement` 只可首次激活已有病情前件的医生名下 fact。不得补全患者省略的医学对象。
- `open_probe` 的 `target` 若仍是 patient_private，台词不得点名该 fact；只能中性问，等患者自己激活。禁止医生轮 `target=患者核心关切` 且台词点名该关切。
- 患者首要诉求必须先安排患者说出口，再安排医生进入该主题。
- 医生名下建议须在相关病情已激活之后，不能当第一句。
- `echo_then_probe` 医生、患者都可用。默认半句（2–6 字）加推进同轮；合计将超约二十字才拆成两行，拆后自己下一轮必须接上问/答/建议。禁止整句回读、禁止「你是问能不能查」类元复述。
- 接对方刚说完的实质轮时，本行优先带 2–4 字已出口词或短确认再推进，不要光用 `嗯` 换题。清单交替处单独 `嗯` 即可。
- `echo_confirm` 不得单独占一轮后停住。必须同轮推进，或紧接着自己下一轮推进；对方可用 `嗯` / `对` 接住。`doctor_echo_mode=high` 不是每条 fact 先 echo 再停。
- 同一人连续实质轮最多 2（建议、药名、征象、解释结论均算）。第 3 条前必须插入对方短回应或半句接话。`complete_set` 用交替全员说出，禁止连发或收成「注意生活」。
- `HABITS` 每名角色至少两条，且至少一条落到可观察的接话方式（半句确认后追问、短答再补、先答再问）。禁止只写「自然 / 耐心 / 口语化」。
- `request_continue` 仅当该行之后仍有未激活的 REQUIRED 事实。
- 每轮 `semantic_groups=1`。`supports` 默认且几乎总是**一个** fact。仅同一 atomic fact 的不可拆极短限定可同轮，不能列出两个独立 fact；`complete_set` 成员、风险征象、否认项、药物、建议和不同时间/来源/极性的 fact 一律一行一个 `supports`。

- 开头列出 `AVAILABLE_FACTS`；结束时 REQUIRED 均已 `activates`。
- `echo_confirm` / `detail_probe` 目标必须已激活。
- `pure_backchannel` 不得出现 `supports` / `activates` / `target`。
- 中性「这次主要想问什么」允许；点名「关于胃镜你想问什么」禁止。不得安排无来源的记忆不清。
- 保留 bindings（含 tense / modality / relation / source_type）。自定义 id 必须按 `CUSTOM_VOCAB` 的 `gloss` 导演，不得忽略 gloss 改强度。不得默认翻病历。不得把「可以」导演成「建议去查」。不得把检查结果导演成「得过某病」。
- 打断默认 none，全对话通常 0–1 次。
- 不要用模型医学知识加戏。
- `REQUIRED_FACTS` 必须包含全部 `LOCKED_FACTS` 以及每个 `complete_set` 的每一成员。结束时这些 ID 均已 `activates`。仅 meta 的年龄/性别不得写入 `REQUIRED_FACTS`。

- 有 `supports` / `activates` 的实质行必须按医学命题等价导演（9 维双向蕴含，不得加「等」、弱化阈值或强化模态）。`pure_backchannel` / `acknowledgement` / `request_continue` / `closure` 为表面层，不得偷渡可记录的医学、行为、身份或计划事实。
- 年龄 fact 仅当 Contract 已锁；由患者/陪诊者中途带出，不得单独开场自报。医生不得问年龄、不得念 meta 年龄。不得安排点名或索要性别。不得把仅 meta / profile / 未在原始台词出现的背景安排进对话。不得把抽象 fact 导演成具体生活动作或停工复工。

- `closure` 不得借收尾新造医嘱。`complete_set` 组未说完不得当已覆盖。
- 同时读 `SOURCE_DIGEST` 与 fact。激活带 `depends_on` 的 fact 时，被依赖 fact 必须已在 `ACTIVATED`，且其关键内容词须安排在**本轮或相邻轮**出口进 `SURFACE`。不强制同一轮说完。禁止把有依托命题导演成无依托清单（发作期否认当平时没有、相对变化当绝对状态、条件触发当确定结论）。有 `depends_on` 的否认不得按 `kind=denials` 穿插到无关问答里。

# Stage 3：Spoken Base

生成已经像线下门诊、但**不刻意添加失流**的自然口语底稿。严格实现 `TURN_PLAN`。底稿是短句接话，不是讲稿：不要在单个 turn 堆砌过多表述。每句台词优先 ≤ 二十汉字，为失流预留余量（本 stage 尽量 ≤ 二十，以便 Stage 4 加字后仍 ≤ 四十）。不得出现 `：` `；`，不得用阿拉伯数字。

编号从 `1` 开始与 TURN_PLAN 对齐。第三列起为许可证，最终 JSON 只保留台词：

```text

```

许可字段照抄 TURN_PLAN 对应行。`supports` 只能表达该轮许可事实。

- 未激活目标：不能「没有吧 / 加重了吧」，也不能点名未说出的主题词（「关于胃镜你想问什么」）。
- 医生台词必须符合该行 `knowledge_basis`。中性开放问可以是「还有别的不舒服吗」「这次主要想问什么」。
- echo 默认 2–6 字关键片段，禁止整句回读和「你是问能不能做」类元复述。字数够则同轮推进（如 `躺下更明显，还有呢？`）；拆轮后自己下一轮必须接上问/答/建议。对方可用 `对` / `嗯` 接住。

- echo 与追问超约二十字不得自行合并。
- 不得把「可以」写成「查一下看看」。不得无来源「记不清」。
- 超二十的台词先拆轮，不要硬压进一行。
- `complete_set` 每个成员都要在许可轮里说出，禁止用「眼睛黄、尿也黄」一类抽样句代替全组。

# Stage 4：Disfluency Plan

你是失流计划器。你只能为 Spoken Base 的每一行规划局部失流和口语句法；不得改写、复述或输出 Spoken Base，也不得输出最终对话，不得再输出人物小传。

优先落在：高 `pressure` 轮的句间组织与功能词；回忆、纠正、术语检索；`answer_then_add` / `partial_answer_then_recall` 转折；改话题；被打断后恢复。不要把省略号只堆在结论/术语前当作拆分的替代。失流仍可碰医学锚点，规则见「口误与医学锚点」。打断残句不得切在医学核心 span 中间。

不要连续多轮人人失流。`none` 不得与事件同行。

规则：

- 每轮默认 0–2 个失流事件；短答 0–1 个；医生通常 0–1 个。
- 实现后该轮汉字数仍须 ≤ 四十。底稿已 ≥ 三十五时本轮写 `none`，或只加一个极短填充，不得用失流把句子顶过四十。超四十应在校验阶段 `split_turn`，不要靠省略号冒充拆分。
- 失流可以碰到医学锚点，但除可理解俗称/口误外，**同一轮必须纠正**到 Spoken Base / `fact_xx` 的正确表达。
- `self_repair` 的 correct anchor 必须是最终正确且受 Clinical Contract 锁定的表达；reparandum 可以是音近误说、半截术语或不准的时长。
- `slip` 仅当对方能完全理解成同一锁定实体时才可不跟 `self_repair`（如甲硝坐≈甲硝唑）。若会变成另一种药、另一种病、错误剂量或错误时长，必须纠正或不要用 slip。
- 医生不能把误说的医学术语、诊断、药物、剂量或检查结果当作最终信息。
- `repetition` 可以重复锚点词，但不要重复成另一种实体。
- 失流只可对同一行 Spoken Base 已许可的文字做停顿、重复、重启或当场修正；不得借 `restart`、`self_repair`、`discourse_marker` 新引入 Contract 的主题词、症状、药物、检查或关切。
- 不加入咳嗽、笑声、叹气、动作、背景声。
- `oral_syntax` 最多一个，只在自然时使用。
- 不要让连续多轮都出现失流。
- `none` 与其他事件不可同一行出现。

## 输入

Clinical Contract + Encounter Plan + Spoken Base 原文。

## 输出格式

```text
<Spoken Base 行号> | <事件>; <事件>; <口语句法>
```
```text
[DISFLUENCY_PLAN]
1 | oral_syntax(topic_fronting)
2 | none
3 | filled_pause(start, "嗯"); self_repair("两周" <- "十来天", "不对")
4 | none
5 | none
6 | none
7 | none
8 | none
9 | restart(start, "这个，呃")
10 | none
11 | none
12 | none
13 | none
14 | none
15 | none
16 | none
17 | none
[/DISFLUENCY_PLAN]
```

### 事件

| 事件 | 格式 | 含义 |
| --- | --- | --- |
| `filled_pause` | `filled_pause(position, "text")` | 插入可转录填充词 |
| `discourse_marker` | `discourse_marker(position, "text")` | 弱语篇词，如「就是」「其实」 |
| `silent_pause` | `silent_pause(position, "anchor", level)` | 在指定位置加停顿，最终统一 `……` |
| `repetition` | `repetition("anchor", count)` | 将 anchor 额外重复 count 次再保留原 anchor |
| `restart` | `restart(position, "abandoned text")` | 先说不完整起句，再回到原句 |
| `self_repair` | `self_repair("correct anchor" <- "reparandum", "cue")` | 先说错/不准 + 修正提示 + 正确表达 |
| `prolongation` | `prolongation("anchor", level)` | 对非关键医学结论的词作轻微拉长；剂量数字慎用 |
| `slip` | `slip("correct anchor", "wrong anchor")` | 可理解且不改命题的嘴瓢；否则必须 `+ self_repair` |

`position`：`start` / `before` / `after` / `replace`。`level`：`short` / `medium` / `long`。

口语句法：`oral_syntax(topic_fronting|fragment|tail_addition|natural_inversion)`。

## 正例

患者回忆病程的那一行适合 `filled_pause` + 对时长的 `self_repair`；药名可用可理解 slip 或立刻修正；医生封闭式危险症状提问写 `none`。禁止把错误剂量/诊断留到句尾还不改。

## 反例

```text
[DISFLUENCY_PLAN]
1 | filled_pause(start, "嗯"); filled_pause(after, "我", "呃"); restart(start, "那个")
```

过密、且 `filled_pause` 参数不合法。也不要缺行、不要把 `none` 和事件写在一起、不要规划咳嗽。

# Stage 5：Surface Generation

按 Disfluency Plan 将变化应用到 Spoken Base，并只输出既定的最终 JSON。输入不含原始线上对话。

逐条执行：

- 不得省略、合并 Spoken Base 的发言轮。顺序、说话人与底稿一致。丢掉行号和许可证列，只把台词写入 `text`。仅当 `repair_targets` 要求 `split_turn` / `insert_turn` 时才改轮次。
- 最终每轮优先 ≤ 二十汉字，含失流硬上限四十。不得出现 `：` `；`。不用阿拉伯数字（药名/检查名原文除外）。
- 不得输出任何中间格式、许可证、计划解释或 Markdown。
- 必须完整实现每个计划事件；未计划的部分保持 Spoken Base 的医学含义与来源许可。
- 最终文本中的所有显式失流都必须来自 Disfluency Plan。碰过锚点的，最终命题仍须等于该行 `fact_xx`。
- 仅用 `……` 表示 `silent_pause`。
- 必须落实 `INTERACTION_PROFILE` 与 HABITS；至少一条 HABITS 要听得见接话方式（半句确认后追问、短答再补、先答再问），不能只剩「自然 / 耐心」。医生与患者的 echo 多少分别跟 `doctor_echo_mode` / `patient_echo_mode` 一致，不按全局配额删 echo。`doctor_echo_mode=high` 是碎信息半句确认再推进，不是每条 fact 整句回读后停住。
- echo 只复述 2–6 字关键片段；纯复述后自己下一轮既无推进、对方也不接应则不合格。禁止「你是问能不能查」类元复述。接对方实质内容时应听得出接住了上一轮；清单交替处单独 `嗯` 即可。
- 同一人连续实质轮最多 2；第 3 条前必须有对方短回应。`complete_set` 用交替交付，不得连发。
- 不得点名或索要性别；不得由医生问起年龄；无原始台词依据不得自报年龄，也不得单独开场自报。`PATIENT_META` / `patient_profile` / 未在原始台词出现的背景不得写入 `dialogue`。
- 实质轮必须医学命题等价；表面轮可改说法但不得新增可记录事实。不得把抽象事实展开、加「等」、弱化阈值或强化模态。不得把医生建议写成患者既往行为或依从承诺。
- `shared` 只能用前文已出口的内容词；不得补全省略对象。
- 患者问句后医生首个实质轮必须答该问、澄清、为答而追问或 `topic_shift`；不得把无关锁定事实接成答案。
- 必须符合 `FACT_BINDINGS`（含 tense、modality、relation、temporal_scope、`source_type`）及 `CUSTOM_VOCAB` 的 gloss。重排不构成偏移；换绑时间/关系/模态/来源则构成偏移。「可以查」不得写成「查一下看看」；「如果可以的话」不得写成「我建议住院」。检查结果不得写成「得过某病」；类药一般说明不得写成个体归因。自定义标签不得压成无 gloss 的空词。
- `request_continue` 不得出现在已无后续内容时。
- 单轮不得堆叠多条建议、多个征象或多种药。`complete_set` 不得抽样摘要。
- 已激活的功能/治疗状态后续不得矛盾。原文先预后后自理的，台词须先激活已自理，再谈现有基础上改善。不得无来源「记不清」。具体治疗对象不得泛化。
- `pure_backchannel` / 纯应答只保留会话功能。
- 实现打断残句时不要加括号；被切断的必要事实必须已在后续轮出现。
- 问句不得把未激活事实当成已知。不得点名患者尚未说出的关切。中性「这次主要想问什么」允许。医生名下建议仅在病情前件已激活后说出。
- 没有括号动作；不残留线上动作。
- 失流不得削平依托。最终台词仍须与 `quote`+`depends_on`+`setting` 医学命题等价；被依赖内容词须在本轮或相邻轮可听见。禁止把发作期否认写成平时没有、相对变化写成绝对状态、条件触发写成确定结论。

## 输入

Output identity JSON（仅 `dialogue_id`、`source`、`meta.sex` / `meta.age` / `meta.language`）+ 四个中间区块原文。identity 不含原始对话或 Stage 0 的 `evidence` / `confidence`，且 meta 不是现场共享知识。

## 输出（唯一最终格式）

```json
{"dialogue_id":0,"source":"","meta":{"sex":null,"age":null,"language":"Chinese"},"dialogue":[{"speaker":"患者|医生|陪诊者","text":"string"}]}
```

# Stage 5：Surface Repair

沿用 Surface Generation 的全部边界。根据 `repair_targets` 做最小、定点修复；保留未被点名的有效轮次。可执行 `rewrite_turn`、`split_turn`、`merge_turn`、`insert_turn`、`remove_turn`、`move_turn`；初次生成的「仅 split/insert 改轮次」限制不适用于 Repair。不得加入 `LOCKED_FACTS` 之外的病例或医学信息，也不得重跑导演或重写整段。不要把中间计划字段写进最终 JSON。

## 输入

Output identity（仅 `dialogue_id`、`source`、`meta.sex` / `meta.age` / `meta.language`）、四个中间区块、`repair_mode`、`previous_dialogue`、`repair_targets`。

## 输出

与 Surface Generation 的最终 JSON 完全相同。

`turn_index` 一律是最终 `dialogue` 数组的 **0-based** 下标。每条 target 必有 `scope=surface`、`action`、`instruction` 和 `preserved_fact_ids`。动作附加字段：

```text
rewrite_turn: turn_index
split_turn: turn_index, split_after
merge_turn: turn_indices
insert_turn: after_index, speaker, supports
remove_turn: turn_index（仅无 supports/activates 的纯回应）
move_turn: from_index, after_index
```

所有动作之后，每个 `preserved_fact_ids` 均保留原说话人所有权、首次激活顺序与完整集合覆盖。不得合并不同 fact 的实质轮；不得删除带 supports/activates 的轮。新增轮只能补回 Contract 已锁且 Plan 已许可的 fact。

## 正例

若目标是预设式问句或主题泄漏（`关于胃镜你想问什么`），改为中性开放问或等患者先说该主题。若一轮超四十或冒号清单，必须 `split_turn`。若「可以做」被写成建议，改回许可语气。若患者未来行动，改为纯 backchannel。打断切断锚点则把切断点挪到功能残句，并补回被吞掉的事实。若 `complete_set` 被抽样，补回缺失成员（可 `insert_turn`），不要用一句摘要交差。若检查结果被改成病史、或一般说明被改成个体归因，改回来源强度。若自定义标签丢掉 gloss，按 `CUSTOM_VOCAB` 改回对应说法。若仍先说「恢复到能独立走路」而后患者已能走，用 `move_turn` 先激活当前能走，预后改为现有基础上改善，不要改医学结论。若牵引被写成治疗，改回牵引。若整句空转 echo，改为半句 echo 并同轮或下一轮推进，或插入对方 `对`。若同一人连续第三条实质内容，在第 2 条后 `insert_turn` 对方短回应。若出现 `请先说下年龄和性别` / `男性` / 无依据的开场年龄，删掉或改为中性接诊。若抽象事实被展开，改回同一抽象层级。若医生补全省略对象，删掉未出口的对象词。若患者问 A 医生答无关 B，改为先答 A 或显式 `topic_shift`。若有依托被削成全称/平时/绝对状态，按 `SOURCE_DIGEST` 与 `depends_on`/`setting` 改回情境或基线，或把被依赖内容词移到本轮/邻轮。

`repair_targets` 用 0-based `turn_index`。每条至少含 `scope`、`action`、`instruction`、`preserved_fact_ids`。`scope=surface` 时 action 只能为 `rewrite_turn` / `split_turn` / `merge_turn` / `insert_turn` / `remove_turn` / `move_turn`；`scope=contract` / `plan` / `spoken_base` 时 action 为 `repair_block`，并列出 `fact_ids`。结构性 target 由 pipeline 调用对应上游 repair stage，再重新生成后续区块和最终 JSON；不得尝试在 Surface Repair 中绕过许可证链。

`turn_audit` 必须覆盖最终每一轮。纯应答轮 `claims` 为空；`answer_then_add` 的 claims 只能来自该轮 `supports`。`claims.relation` 只允许 `equivalent`（医学命题双向蕴含）。`expansion` / `weakening` / `extra` / 仅词义相近的 `paraphrase` 均失败。不要问「内容是否大致正确」。

无来源新命题：

```json
{
  "turn": 13,
  "license": "pure_backchannel",
  "status": "repair",
  "error": "unsupported_proposition",
  "claim_type": "future_plan",
  "repair": "replace with a pure acknowledgement or request_continue"
}
```

对应 surface `repair_targets` 例如：`{"scope":"surface","action":"rewrite_turn","turn_index":12,"preserved_fact_ids":[],"instruction":"将该患者未来行动改为纯 backchannel；保留后续事实顺序。"}`。对应结构 target：`{"scope":"plan","action":"repair_block","fact_ids":["fact_07"],"preserved_fact_ids":["fact_07"],"instruction":"将医生首次医嘱改为 doctor_statement，并保持病情前件先激活。"}`。

## 判定细则

- `medical_proposition_equivalence`：**主检查**。不要只问「内容是否大致正确」。对每个带 `supports` 的最终轮，相对该 `fact_id`（`quote`+`depends_on`+`setting`，并对照 `SOURCE_DIGEST`）做三项：① 输出是否蕴含原医学命题（不漏、不弱化、不削平依托）；② 原医学命题是否蕴含输出（不扩展、不强化、不加「等」）；③ 输出是否额外蕴含新的医学/行为/身份/计划命题。①+② 近似双向蕴含；③ 拦截加戏。纯表面轮（无 supports 的 backchannel / acknowledgement / request_continue / closure）只跑 ③。任一项失败则本规则失败。`未进食`→`吃得很少`、`检查提示某病`→`以前得过`、`可能与用药有关`→`就是药物导致`、`任一项出现即就医`→`严重了再就医`、`某病毒`→`某病毒等病毒`、`咳嗽时胸口疼`→`平时胸口疼`、`比上周轻`→`很轻` 均失败。
- `locked_fact_coverage`：每个 LOCKED_FACT **以及每个 complete_set 的每一成员**均须在对话中激活并出现。抽样摘要（如只说「眼睛黄、尿也黄」代替全组）失败。组未说完不得标 covered。
- `complete_set_integrity`：每个 `FACT_SETS.members` 必须是 `LOCKED_FACTS` 中的不同原子 ID；`complete_set` 至少两个成员，且组未说完不得宣称已覆盖。触发条件不得因列表残缺而减弱。「出现则就医」在成员被漏掉后变弱则失败。
- `source_type_fidelity`：检查结果 ≠ 病史独白；一般医学说明 ≠ 对该患者此刻的个体归因；条件性建议 ≠ 确定结论；具体治疗对象不得上位泛化（牵引 ≠ 治疗）。跨 `source_type` 族失败。患者自述应标 `patient_report`。缺失的 `source_type` 不得自行升级。自定义 id 的 gloss 须写所属族，不得跳族。
- `clinical_fidelity_and_modality`：不新增/反转/强化。「可以查」不得变成「可以查一下看看」或「建议你去查」。「如果可以的话到康复科」不得变成「我建议住院」。无原文强调不得加「一定要记住」。时间阈值不得改约数（`六小时以上` ≠ `六个多小时`）。与 `polarity_modality_temporality` 对齐，不互相打架。
- `fact_binding_and_provenance`：逐项核对 bindings（含 `source_type`、`quote`、`depends_on`、`setting` 与九维：主体、内容、时间、极性、程度、模态、依托、范围、来源）。`status` 只核极性，不把「何时成立」算进 `status=条件`。有来源/强度差异的 fact 漏写 `source_type` 失败；非目录短词必须出现在 `CUSTOM_VOCAB`，且 `field` 与引用字段一致、`gloss` 完整（含义 + 落地 + 所属族 + 禁区）；无 gloss 或 gloss 只有一个词则失败。`owner` 不得自定义。不得把「做过两个月理疗」加成「刚得病那会儿做过」。
- `license_chain`：未修复时最终第 n 轮对上 Spoken Base 第 n 行；命题 ⊆ supports/target/bridge。修复后每轮须映射到 `spoken_base_line` 或 `repair_inserted`，并携带其 `fact_ids`。按顺序模拟 `ACTIVATED` 集合。
- `knowledge_basis_consistency`：每个医生 turn 的 `shared` 内容须已激活**且**内容词 ⊆ 当时 `SURFACE`；`neutral_open_question` 必须事实盲；`doctor_statement` 必须首次激活医生名下 fact 且已有病情前件。患者/陪诊者来源 fact 若首次由医生激活则失败。
- `no_synthetic_case_detail`：不新增症状、时间、诱因、检查、陪诊、病历、开单、无来源「记不清」。与 `meta_surface_leak` / `specificity_expansion` 对齐。
- `meta_surface_leak`：`PATIENT_META`、`patient_profile`、仅输入未台词的背景写入 `dialogue` 失败。`请先说下年龄和性别`、答 `男性` / `女性`、医生问起年龄、无原始台词依据的开场「四十二岁」失败。不得用「先问再答」或「医学判断需要」放行年龄/性别。
- `specificity_expansion`：`medical_proposition_equivalence` 的特化。抽象 fact 被降一层展开失败。「能独立走路」→ 买菜做饭；「已上班」→ 停工后复工；「未进食」→「吃得很少」；加「等病毒」；医生建议变成患者既往行为、依从承诺或生活习惯。仅词义相近不算通过。
- `polarity_modality_temporality`：改变时态、极性、程度、频率、阈值、模态、条件或适用范围失败。当前治疗 ≠ 既往查出；完全否定 ≠ 部分否定；「可以」≠「建议必须」；一般说明 ≠ 个体归因；条件描述 ≠ 确定结论。与 `clinical_fidelity_and_modality` / `fact_binding_and_provenance` 同一标准。
- `question_presupposition`：未激活事实被确认式/预设式提问则失败。`加重了吧` 失败；`这两天整体有什么变化吗` 在未激活时通过。
- `context_leak`：对**每一个医生 turn**，其中出现的具体主题词、症状词、检查词、治疗词、患者担忧或事实判断，必须能在**此前 dialogue 台词**找到明确前件，或是合格 `doctor_statement` 首次给出的医生名下 fact。Contract 有 ≠ 现场已说。患者来源事实绝不可借此例外提前说出。未激活事实只能由事实盲问题引出；含候选答案、方向、时间、程度、因果、否定、诊断名或治疗名的问句均失败。`关于胃镜，你想问什么`、`加重以后吐过吗` 在患者未提加重时均失败。开场就针对某主题给建议失败。修复：`rewrite_turn` 为事实盲中性问，或等患者先说该主题。
- `activated_context_leak`：激活看已说出口的内容词，不是 Contract 槽位。医生 `shared` 不得补全患者省略的医学对象（「做过三周」不得被补成「牵引做了三周」），也不得点名未说出的病名、药物、检查、治疗或时间。fact_id 已在 `ACTIVATED` 但该对象未进 `SURFACE` 仍失败。
- `bridge_license`：过渡轮不得新增无来源事实、依从承诺、开单/病历、身份关系。患者私有关切不得由医生先开口。
- `turn_function_density`：默认一轮一个 `fact_xx`。只有同一 atomic fact 的不可拆极短限定可同轮，且不得额外承载独立 fact、不同时间/来源/极性。任何 `complete_set` 成员、建议、征象、否认项、药物都不得以双事实同轮交付。字数优先于「一组说完」。
- `short_turn_rhythm`：最终 `text` 优先 ≤ 二十汉字；**超过四十汉字失败**，`action` 用 `split_turn`。不要仅为交替而 insert；同一人已连续两条实质内容、即将出现第三条时必须 insert 对方短回应。
- `spoken_punctuation`：台词含 `：` 或 `；` 失败。台词含阿拉伯数字（药名/检查名原文除外）失败。`小伙子28岁` 失败。点名性别或索要「年龄和性别」失败。
- `format`：无动作括号、无中间字段；未要求拆轮时轮数与 Spoken Base 一致。
- `patient_intent_scope`：不得收窄泛化诉求。
- `bridge_purity` / `listener_response_purity`：表面层不得偷渡可记录的医学、行为、身份或计划事实。`嗯` `好` `我明白了` `您继续说` `这个我听懂了` 通过。`我烟酒都少碰` `我会按时去做` `我以前停过工` `我后面安排` `我会坚持` `我就放心了` 失败。
- `question_license`：每个问句必须有 target 与 question_mode。中性开放问可不带具体 target。
- `role_ownership`：`owner=医生`、`provenance=医生说明|医生建议` 的当前诊断/解释/医嘱须由医生首次说出；患者/陪诊者只能在该 fact 已激活后 echo，或按 binding 明确转述既往内容。`owner=患者|陪诊者` 的事实不得由医生首次 `activates`。陪诊者出现时必须有对应 `owner=陪诊者` 或 `relation=代述者` 的 fact。
- `state_consistency`：已说出的能力、工作/治疗、症状与否认、已做/未做检查治疗、预后目标 vs 已达功能不得矛盾。已激活「能独立走路」后不得再把独立走路当未实现目标；「正在治疗」不得改成已经结束。原文内冲突时优先保留明确、具体、当前时态的患者陈述。若生成仍先说「恢复到能独立走路」而后患者已能走，则 `repair` 为 `move_turn` 重排（先激活当前状态，预后改为现有基础上改善），不是改医学结论。
- `adjacent_relation_and_state_consistency`：上一轮是患者问题（疑问 fact 或问号）时，下一位医生的首个实质轮必须回答、澄清、为回答所必需的追问，或显式 `topic_shift`。`topic_shift` 须先结束当前问。把同段原文里无直接问答关系的锁定事实接成答案失败（问生活限制、答风险征象）。`reacts_to` 必须指向被回答的上一问，或为 `none` 且不假装在答。状态一致性同 `state_consistency`。`complete_set` 组未说完不得标 covered。
- `request_continue_timing`：「您接着说」等仅当该轮之后仍有计划中未表达内容。医嘱已说完仍请求继续则失败；医生并无下文则失败。
- `interaction_rhythm`：同一人连续实质轮（建议、药名、征象、解释结论、新事实）最多 2；第 3 条前无对方短回应或半句接话则失败。连续多组实质表达完全无 Listener Response 也失败；回应过密且句句相同也失败。医生连续两轮短建议可以 pass，连续第 3 条失败。纯复述且下一轮既无推进也无对方接应（`嗯` / `对`）失败；整句回读或「你是问能不能查」类元复述失败。不得因任一方 echo 次数未达某配额而失败。`complete_set` 连发无人接话不得用「注意生活」一类摘要抵消。
- `interruption_integrity`：打断切断医学核心 span、打断者无来源、或必要事实被永久吞掉则失败。短对话通常最多一次打断。
- `coverage_after_reordering`：拆分、重排、插回应之后 REQUIRED / LOCKED_FACTS / `complete_set` 全员仍须全部出现，不得丢掉病情变化、风险触发条件、建议中的某一项或患者核心问。
- `offline_realism`：无线上平台痕迹；无 fact 则无病历表演。须像门诊 ASR 转写，不像文学简写或清单导演。点名性别、索要年龄性别、无台词依据自报年龄失败。
- `persona_realization`：`INTERACTION_PROFILE` 与 HABITS 必须匹配且可听见。至少一条 HABITS 落到接话方式（半句确认后追问、短答再补、先答再问）；只写「自然 / 耐心」或标签在字面上听不见则失败。`doctor_echo_mode=high` 必须表现为半句确认再推进，不是每条 fact 整句 echo 后停。不得把 echo 判成医生专属错误。输出须像 ASR 门诊转写，把每条 fact 做成「陈述—整句 echo」清单对则失败。
- `disfluency_fidelity`：失流可碰锚点，最终命题须正确或为可理解口误。加失流后仍须 ≤ 四十汉字。
- `spoken_naturalness`：五个以上实质轮不能只有「嗯」而无其他口语结构。对方刚说完实质内容、本轮完全无接应就换无关主题则失败；清单第二条前单独 `嗯` 通过。不因同一人连说两轮而失败；连说三轮实质内容失败。禁止讲稿腔连接词堆叠。禁止文学对话简写（整句空转复述、无人接应的宣教切开）。
- `digest_fact_alignment`：`SOURCE_DIGEST` 与 `LOCKED_FACTS` 必须覆盖同一批原文医学命题。一边有情境/条件/基线/来源/触发，另一边写成无依托，则失败。有依托的否认被收进 `kind=denials` 失败。陈述或 fact 漏掉原文已有依托 → `scope=contract`，两路一起修，不要只改一边。
- `quote_fidelity`：每条 fact 的 `quote` 是能完整表达该命题的全部原文子串（`+` 连接）。输入含原始对话时，**每一段**都必须是原始台词子串。各段合在一起必须双向蕴含该命题（含对象、依托、极性、触发）；只摘孤立 value、漏掉「咳嗽的时候 / 蹲下 / 比上周 / 要是」等依托片段则失败。不得把子串改写成新句，不得从 `SOURCE_DIGEST` 抄。该轮台词相对整组 `quote`+`depends_on`+`setting` 做医学命题等价。
- `dependency_adjacency`：带 `depends_on` 的实质轮，被依赖 fact 必须已在 `ACTIVATED`，且其关键内容词已在**本轮或相邻轮** `SURFACE`。未激活或隔开后只剩全称/平时/绝对状态则失败。泛化反例：发作期否认→平时没有；只在某动作成立→一直如此；相对变化→绝对状态；条件触发→确定结论；检查来源→本人病史。不限于某一种症状配对。

修复必须定点，例如：`将该预设式问句改为中性开放问。` `将「关于胃镜你想问什么」改为等患者先说胃镜，或改成「这次主要想问什么」。` `将该超长清单拆成每条一轮。` `将「可以做一下看看」改回「胃镜能做」。` `补回 complete_set 未说出的成员。` `将检查结果改回「以前检查说是……」，不要写成得过某病。` `将类药一般说明改回「这类药会有这方面副反应」，不要写成个体归因。` `按 CUSTOM_VOCAB 的 gloss 重写该轮，不要只用一个自定义单词。` `先激活已能独立走路，预后改为现有基础上改善。` `将「三周治疗」改回「三周牵引」。` `将整句空转 echo 改为半句确认并同轮或下一轮推进。` `在连续第 2 条实质内容后插入对方短回应。` `删除「请先说下年龄和性别」及「男性」，改为中性接诊。` `将买菜做饭改回能独立走路，不要展开抽象事实。` `删除医生补出的未出口对象词。` `患者问生活限制时先答该问，或显式 topic_shift 后再给风险。` `将「吃得很少」改回「还没吃」。` `删掉「等病毒」。` `将「严重了再去急诊」改回任一项即就医。` `将「就是药物导致」改回「可能跟药有关」。` `将「平时胸口疼」改回「咳嗽的时候胸口疼」，并让咳嗽在本轮或邻轮可听见。` `将「老是晕」改回「蹲下才晕」。` `将「很轻」改回「比上周轻」。` `将隔开后的「躺下都不舒服」改回邻轮仍能听见反酸的「躺下更明显」。` `陈述与 fact 依托不一致时 scope=contract 两路一起补。`

涉及事实偏移仍用 fact_id 结构。

## 正例

书面过整 → 指定一处倒装或省略。`关于胃镜你想问什么` → 中性开放问或等患者先说。超四十或冒号清单 → `split_turn`。未来承诺 → 纯 backchannel。已纠正的 `胃……胃镜` → pass。医生在症状激活后说己方生活建议 → pass。抽样风险组 → 补全成员。先预后独立走路后已能走 → `move_turn`。无 gloss 的自定义 slug → repair。整句 `你担心要一直压着。` 后无下文 → 改为 `躺下更明显，多久了？` 一类半句 echo + 推进，或插入对方 `对`。连续第三条生活建议无人接话 → `insert_turn` 短回应。`请先说下年龄和性别` / `男性` / 无依据「四十二岁」 → 删除。`自己能买菜做饭` → 改回 `能独立走路`。患者 `做过三周` 后医生点名牵引 → 删未出口对象。问生活限制答风险 → 先答或 `topic_shift`。`未进食` 写成 `吃得很少` → 改回完全否定。`某病毒等病毒` → 删「等病毒」。`严重了再去急诊` → 改回任一项即就医。`就是药物导致` → 改回「可能与用药有关」。`平时胸口疼` → 改回咳嗽时胸痛且邻轮点明咳嗽。`老是晕` → 改回蹲下时。`很轻` → 改回相对上周。陈述有依托、fact 无依托 → `scope=contract` 两路补。依赖未在相邻轮点明 → 重排或补回被依赖内容词。
