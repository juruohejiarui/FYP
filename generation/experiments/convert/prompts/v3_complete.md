# Medical Dialogue Rewrite Pipeline

## 全局 JSON 契约（适用于全部 stage）

- 下文 JSON 代码块是结构示例；示例中的 string、整数、null、... 都是类型说明，不是要原样输出的字符串。
- A | B | null 表示该字段只能取枚举值 A、B 或 JSON 的 null；不能输出包含竖线的文字。
- 每个示例对象中出现的字段均为必填字段，除非字段后明确标注“可选”。数组可以为空数组 []；不确定值只能用 null，不能省略字段或用“未知”代替。
- 只能输出一个顶层 JSON object。所有字段名、层级、类型必须与对应 stage 的输出格式一致；不得新增顶层字段。
- Stage 0 的输出由 pipeline 合并回输入 meta；Stage 1–3 的输出只供下游使用；只有 Stage 4 的输出会写入最终 JSONL；Stage 5 不会写入最终 JSONL。

<!-- STAGE: stage0_meta_inference -->
# Stage 0：Meta Inference

你只补全输入 `meta` 中缺失的 `sex`、`age`、`language`；不改写对话，不推断性格、情绪或口语习惯。只输出 JSON。

## 规则

1. 仅填补 `null`、空字符串、`unknown`、`none` 等缺失值；已有字段原样保留。
2. 只有原文直接给出或具有强而无歧义的医学语义时才推断。证据不足必须为 `null`。
3. `sex` 仅为 `男`、`女`、`null`；`age` 为整数或 `null`；中文对话的 `language` 为 `Chinese`，否则为 `null`。
4. 不得把疾病、年龄或性别映射成焦虑、结巴、健谈等人物设定。

## 输入格式

```json
{"dialogue_id":0,"source":"","meta":{"sex":null,"age":null,"language":null},"dialogue":[{"speaker":"患者","text":"..."}]}
```

## 输出格式

```json
{"sex":"女 | 男 | null","age":"整数 | null","language":"Chinese | null","evidence":{"sex":"string","age":"string","language":"string"},"confidence":"high | medium | low"}
```

## Few-shot

若患者首句为“（女，二十一岁）慢性荨麻疹能查过敏原吗？”且三项 meta 均缺失：

```json
{"sex":"女","age":21,"language":"Chinese","evidence":{"sex":"患者首句明示女","age":"患者首句明示二十一岁","language":"对话为中文"},"confidence":"high"}
```

<!-- STAGE: stage1_fact_lock -->
# Stage 1：Fact Lock — 事实锚点

从原对话抽取**不可被创作改变**的医学与沟通事实。你不是摘要器：只抽取，不解释、不补全、不纠正。只输出 JSON。

## 原则

1. 每个事实必须可定位到原始话轮，并区分患者陈述、医生判断、医生建议和患者问题。
2. 必须保留否定、频率、程度、时长、不确定性和问句方向，例如“偶尔”“没查过”“可以”“考虑”。
3. 不得从常见诊疗流程补出症状、检查、诊断、药物、病因或风险提示。
4. 将同一事实的重复出现聚合，但不得把不同事实合并。原始错别字或同音词只在无歧义时规范到 `normalized_text`。

## 输入格式

输入为原始对话 JSON，格式同 Stage 0。

## 输出格式

```json
{
  "fact_ledger":[{
    "id":"F1","turn_indices":[0],"speaker":"患者",
    "kind":"symptom | history | test_status | diagnosis | drug | advice | question | negation | other",
    "source_text":"原文片段","normalized_text":"保留限定词的最小语义表达",
    "certainty":"confirmed | denied | tentative | question",
    "preservation":"must_preserve | may_merge_if_redundant"
  }],
  "core_facts":["F1"],
  "medical_boundaries":{"must_not_add":["..."],"must_not_strengthen":["..."],"must_not_reverse":["..."]}
}
```

`core_facts` 必须覆盖主诉、时长/频率、否认项、既往检查或诊断、药物，以及医生明确给出的建议或解释。患者提问也必须保留其问题方向。

## Few-shot

对“有时尿痛，但不是经常痛”，应保留限定，不能改成“持续尿痛”：

```json
{"fact_ledger":[{"id":"F1","turn_indices":[0],"speaker":"患者","kind":"symptom","source_text":"有时尿痛，但不是经常痛","normalized_text":"偶尔尿痛，非经常发生","certainty":"confirmed","preservation":"must_preserve"}],"core_facts":["F1"],"medical_boundaries":{"must_not_add":[],"must_not_strengthen":["不得改为经常尿痛"],"must_not_reverse":[]}}
```

<!-- STAGE: stage2_scene_adaptation -->
# Stage 2：Scene Adaptation — 线下场景与创作空间

把线上碎片问答迁移为可信的线下面诊场景。你不写最终台词，但可以设计一条**不同于原文逐句排列**、仍忠于事实的咨询路径。只输出 JSON。

## 事实边界

- `fact_lock` 是硬约束：不新增、删除、反转或强化医疗事实。
- 保持总体目的与临床逻辑相近即可，例如“患者主诉/担忧 → 医生围绕已有信息确认 → 原有解释或建议 → 患者确认”。不要求保留原话轮顺序、问句措辞或精确轮次数。
- 可把线上用语改为线下动作；可合并、拆开、重排已有事实；可加入不含医学新信息的开场、理解确认和结束语。
- 不得因为要“像面诊”而补全病史、检查、鉴别诊断或健康宣教。

## 线上内容清理与线下改写

逐条扫描原文中不可能原样出现在面对面门诊的内容，并写入 offline_transforms：

- 远程操作/平台行为：发照片、上传、发来看看、语音视频、平台、在线回复、刚刚才看到、稍后回复等。删除无意义的远程状态，或改写为当面可执行的表达。
- 远程检查请求：如“发个照片让我看看伤口”，若该伤口/检查事实本来存在，可改为“我看一下伤口”；不得添加括号动作、拍照、上传或原文没有的检查。
- “刚刚在开车/我在外面/等会儿到”若只描述线上发送时的当前状态，应删除；但若它是症状发生的时间地点背景，如“开车时突然头晕”，必须保留为病史并改成自然叙述。
- 线上寒暄、客服套话和异步沟通痕迹可删除；不能删掉其中携带的症状、时长、检查或治疗事实。
- 其他一切在线下不需要通过语言阐述，可以直接通过视觉观察/听觉得到的信息，比如：
  - 病人阐述自身性别/外貌，医生可以眼睛直接观察到患者外表得到结果，可直接删除此类文本。
  - 医生也不会重复或者确认病人的性别，可以直接删除医生对性别的确认。

## 口语风格设定

不从年龄、性别、疾病推断性格。你可以为两人自由设计**不改变事实的临场人设**，如
- 患者说话急、先铺垫后提问；
- 医生耐心但有轻微口头重复、会 echo 患者；
- 医生表达快、偶尔在术语前重启。
- 两人的表达的可以不止一个的常驻的习惯，包括但不限于：
  - 爱用倒装句
  - 爱用语气词，语气词可以常用一个（比如经常用“呃”）也可以多样化（那就这样吧，好的哈...）
  - 比较结巴
  - 爱echo
  - 口头重复
- 患者有可能有一定医疗知识，知识的掌握程度有高低之分，医疗知识会影响患者发言的习惯，也会影响其发言习惯/口癖/用语，原因包括但不限于：
  - 长期经受慢性病有一定自我管理能力
  - 是一个医疗工作者
  - 医疗相关专业的学生
  - ...
- 患者可能完全没有医疗知识，知识的缺乏会影响患者发言的习惯，也会影响其发言习惯/口癖/用语；
- 医生的医学知识水平的高低，也会影响其发言习惯/口癖/用语，原因包括但不限于：
  - 对这类病症不熟悉
  - 比较疲惫
  - 工作时间不长

**注意**：两人的差异是医学知识与解释权，不是“医生永远流畅、患者才会结巴”。人设不得新增病史、情绪事实或诊疗结论。

## 输入格式

```json
{"original_dialogue":{...},"fact_lock":{...}}
```

## 输出格式

```json
{
  "visit_frame":"initial_consultation | follow_up | results_discussion | self_medicated_revisit | unclear",
  "offline_premise":"患者因……到门诊咨询",
```

若原文只问“查到过敏原是否需要一直忌口”，并已有回答“体质会变化”，可选 `concise_QA`；`forbidden_additions` 必须包含“不得新增具体忌口清单或检查项目”。

# Stage 3：Turn Planning — 事实驱动的自由问诊骨架

为最终对话制定一个可创造性实现的骨架。你规划的是**意图、事实覆盖与节奏**，不是逐句复刻或最短路径。只输出 JSON。

## 规则

1. 每个 `fact_ids` 必须来自 fact_lock；每项核心事实至少覆盖一次。可把重复事实并入同一自然话轮。
2. 原始轮次、顺序与措辞不是硬约束。允许在不改变医疗因果和说话人立场的前提下重排、拆合，并加入简短的非医疗性确认/开场/收尾。
3. 新增话轮不得引入任何可被患者当成病情、检查、诊断、药物或医嘱理解的新信息。
4. 对话可比源文本长或者短；以完整、自然的面诊节奏为准，禁止为凑轮数机械追问，鼓励不按照源文本的节奏和用语。
5. 只给“可以自然犹豫”的沟通位置，不预写完整台词。医学术语、药名、治疗名和医嘱也可以有重启、结巴、嘴瓢或词汇检索；但一个 turn 结束时必须让听者能还原 fact_lock 中正确的医学含义。
6. 原始单个长发言包含两个以上事实组/提问组时，必须（最好）拆成两个或以上短话轮。可在中间插入对方的短确认、回声复述，或只为引出**紧接着已有事实**的上下文追问。
7. 可以重新编排事实，使其更符合逻辑，更通顺。
   1. 尽量少让一个问题在延后几个turn之后再得到回应，除非这个问题的答案需要一定的前置/补充信息或者追问。
8. 不建议医生询问/确认先前对话中完全没有出现过的症状/治疗/既往病史，最好由患者主动说出，医生再进行确认/回应。
9.  允许的切分桥接包括但不限于“嗯”“这样啊”“后来呢”“当时看过没有”“吃了以后怎么样”；前提是答案已在 fact_lock 中。不得为切分而问没有答案的新症状、风险、检查或治疗问题，更不能让对方编造回答。
10. **硬性规定**：不能由患者主动提出医疗建议/处方/药物策略，最好由医生主动提出。除非患者人设是上述提到慢性病患者。
11. 根据两人的人设，进行有机互动，而不是单纯两个独立的表现。

## 输入格式

```json
{"original_dialogue":{...},"fact_lock":{...},"scene_adaptation":{...}}
```

## 输出格式

```json
{
  "turn_plan":[
    {"speaker":"患者","intent":"主诉 | 补充 | 回答 | 担忧/追问 | 确认 | 致谢 | 开场",
     "fact_ids":["F1"],"creative_freedom":"high | medium | low",
     "speech_context":"plain | thinking | recalling | sensitive_expression | technical_information"}
  ],
  "coverage":[{"fact_id":"F1","planned_turns":[0]}],
  "optional_social_turns":[{"position":"before_turn_0","purpose":"线下问候","adds_medical_fact":false}],
  "dialogue_rhythm":"brief_QA | patient_narrative_then_QA | explanation_led",
  "long_turn_splits":[
    {"source_fact_ids":["F2","F3","F4"],"split_after":"F2","bridge_speaker":"医生","bridge_type":"acknowledgement | echo | contextual_follow_up","bridge_goal":"只引出 F3/F4"}
  ],
  "disfluency_opportunities":[
    {"turn":0,"type":"filler | pause | restart | emphasis_repeat | echo，可以包含若干个这类标签","reason":"组织主诉/回忆/表达顾虑","optional":true}
  ]
}
```

`disfluency_opportunities` 是 Stage 4 的执行计划，不是纯备注：

- 有五个及以上实质话轮时，必须给出二到四个候选位置；若干个是 `restart` 或 `emphasis_repeat`，且若干个可用 `filler`、`pause` 或 `echo`。
- 候选可以落在主诉组织、回忆、担忧追问、接话确认、已有事实的范围澄清，也可以落在药名、诊断名、检查名、治疗名或医嘱的词汇检索处。后一类必须在同一 turn 或紧随其后的对方澄清中落回 fact_lock 的正确名称/含义。
- 少于五个实质话轮时可只给零到一处；不要让每名角色机械各分一处，也不要把“自我修正”列为默认项目。

`long_turn_splits` 是必填数组；没有需要拆分的长发言时输出 []。每一条 bridge 都必须注明它将引出的既有 fact IDs，避免 Stage 4 用“还有什么不舒服”之类的无根据开放式提问扩写病史。

## Few-shot

患者需回忆“以前查没查过过敏原”时，可标一项 `{"turn":1,"type":"filler","reason":"回忆既往检查","optional":true}`；医生解释“体质会变化”则用 `technical_information`，不要安排结巴机会。

# Stage 4：Surface Realization — 自然转写式门诊对话

你是专业的中文门诊录音的人工转写编辑兼文学素养极高，精通人类日常口语对话的对话写作者。根据事实账本和骨架，写成听起来像没有脚本、但信息准确的线下面诊对话。只输出指定 JSON。

## 优先级

1. 医疗事实、否定信息、说话人立场和不确定性准确；
2. 咨询目标与整体流程和原对话相近；
3. 自然的线下互动与可朗读的转写感；
4. 具体措辞、句子切分、顺序和节奏的创造性；
5. 两人人设的有机互动。

不要逐句改写源文本：在上述边界内，自行决定谁先说明、何处追问、何处合并或拆开、用什么日常说法表达。允许对话有自己的节奏，不要像把线上聊天逐条搬进门诊。

## 允许的创造性

- 重排、拆合、压缩源话轮；把重复内容改为一次自然确认；将线上问法改成线下面诊表达。
- 增加“你好，请坐”“嗯，我明白你的担心”“好，知道了”这类不含新医疗事实的衔接。
- 患者可以先叙述再提出担忧；医生可以先确认已有信息，再给出原文已有的解释或建议。
- 允许少量自然的口语词、停顿、重复、起句重启与自我澄清。它们服务于正在组织语言的人，而不是装饰。

## 转写感规则：少量、局部、有动机

可使用“嗯、呃、啊、这个、就是、哦、对对”等语气词。它们尤其适合开场、接话、思考衔接、回忆、表达担忧、接受信息或轻微确认。可保留一两处 `……`、轻重复或不完整起句；不需要分配到每个人或每个话轮。

### 创造性与随机口语层

在事实和流程边界内，主动让每次生成拥有不同的、可信的口语分布。每个 turn 可以包含零个、一个或若干个以下现象；不要整个对话只使用同一种，也不要按固定位置或固定次数注入，我们鼓励注入更多的生成，过少的：

- 重复/结巴：就就这段时间、没……没查过、上班上班就晕；
- 嘴瓢或口误：可不修正，只要对方和读者仍能凭上下文理解，并且不把事实变成别的疾病、药物或建议；
- 倒装，鼓励使用，两广地区比较常见：比如：
  - “这个药有用吗？”->“有用吗这个药？”；
  - “这是啥问题”->“啥问题啊这是？”；
  - “这样可以的。”->“可以吧这样。”；
  - “说是有点缺钠。”->"有点缺钠说是。”；
- 省略表达：以前有过。后来又来了。、那个检查，没做。；
- 语气词与无用内容：呃、嗯、这个……、那个怎么说呢；
- 局部语法不完整或换说法：应该大概是这样？、饮食我很，已经很注意了。；
- 自我修正、术语重启、echo 或短暂卡壳。

这些现象可以单独出现，也可以在同一 turn 叠加，例如“这个……我我之前也有过，应该大概是这样？”；也可以完全不出现。选择应由 Stage 2 的人设、当前信息压力、对话节奏和一次生成的随机变化共同决定。不要把每一 turn 都写得破碎；在一段对话中保留若干干净短句，才能显出真实的起伏。

对五个及以上实质话轮，积极选择至少一处自然的结构性口语变化：倒装、省略、词序重排或不完整起句。它必须适合当句语义，例如患者担心疗效时“有用吗这个药？”、问诊结尾“那现在怎么办我这？”；不合适时可换成省略或词块重复，不能生硬把每句倒装。

### 俚语与日常口语

在不损害医学含义和角色关系的前提下，积极使用自然口语替换书面表达，并随人设变化：肚子、上厕所、尿尿、拉屎、看病、吃药、没啥用、不见好、堵得慌、咋回事、这毛病、反反复复、拖着、得、要不、行、没事儿、挺难受的。患者可以更生活化；医生也可以简洁亲切，如“这个先别拖着”“没啥大问题咱先观察”，但不能把原文没有的风险、安慰或治疗结论塞进去。

### 短回复要有变化

不要把所有短 turn 写成“好”“嗯好”“知道了”。根据上一句的沟通功能、两人人设和当前情绪自由切换：

- 听懂/确认：行、成、哦、这样啊、明白了、那我懂了、可以、对对、是这么回事；
- 仍有顾虑：那怎么办啊？、这样也行？、那我先查查？、不会一直这样吧？；
- 医生承接：嗯、我知道了、这样啊、行、那就对上了、先别急、我问你一句；
- 结尾：那行，谢谢您、好嘞医生、麻烦您了、成，我明白、那我先这样。

可加入轻微重复、语气词或省略，例如“哦……这样啊”“行，那先这样”。同一种短回复在相邻三个 turn 内最多重复一次；若原文只表达确认，可换词但不得借机新增医疗态度或新的追问。

- **可见转写特征的软目标**：五至十个实质话轮的对话，通常实现二到四处可听见的转写现象，其中至少一处应为起句重启/词块重复，而不只是“嗯、哦”。十个以上实质话轮通常实现四到八处，允许集中在患者的一段叙述中。少于五个实质话轮可以只有零到一处。
- Stage 3 已标出的 `disfluency_opportunities` 中，除非实现会破坏事实或句子可懂性，应至少实现两处；不要把全部候选都删成流畅书面语。
- 可用形态包括：起句重复（“就就这段时间”“没没查过”）、词块重复（“上班上班就晕”“休息休息”）、半句重启（“我就……就过来了”）、词汇检索（“那个，我想想”）、范围澄清（“有点痛……也不是经常痛”）、医生 echo（“休息后就好了是吧？”）和轻微嘴瓢后用上下文完成词义。
- 不流利允许局部聚集：患者或医生在一个较长主诉、解释或敏感追问中有一两处，比每句各塞一处更真实。医生与患者都可有无修正口误，只要临床含义仍可还原。
- 自我修正可用于范围、频率、程度、术语检索或表达换说法，例如“有点痛……也不是经常痛”“过敏……过敏原那个检查”。禁止先捏造一个与 fact_lock 相反的医疗事实再撤回。
- “……”仅表示有意义的停顿、迟疑、被截断或未说完；不能代替逗号。
- 医生也可有“嗯”“这样”“那”一类接话词、词块重复、嘴瓢和术语重启，例如“过敏……过敏原可以查”“这个叫、叫沙巴棕胶囊”。专业性体现为最终医学概念、建议和不确定性正确，而非永远无口误。
- 不计数、不设配额。大多数短轮可以完全顺畅；若删去某个语气词后说话人的思考、态度或转折完全不受影响，优先删去它。
- 长句子切分后得到的短句，可以并鼓励添加连接词，比如：“对，还有...”，“嗯，是。...” ...

## 硬边界

- 只能表达 fact_lock/turn_plan 已覆盖的医疗信息。不得补症状、病史、检查、诊断、药物、病因、风险或建议。
- 不得把“偶尔、没有、可以、考虑”等改为确定、频繁、必然；不得将患者问题改成既成事实。
- 不使用网络问诊用语（上传、发来、平台、在线等）。数字写为汉字；不用括号动作说明。
- 必须执行 Stage 2 的 offline_transforms。远程状态、平台套话和远程动作不得残留；保留的症状发生背景需改成线下自然叙述。
- 单个 turn 不超过六十个汉字。可有自然开场和收尾，但避免每句都寒暄或解释。
- 六十字只是硬上限，不是目标。通常每个 turn 控制在八至三十个汉字、只推进一个事实组或一个沟通动作；超过约三十五字且含两个以上事实组时，优先拆成连续短轮。
- 拆分时允许创造性地插入短回应、echo 或上下文追问。例如患者已说“先胃疼、做过胃镜、后来吃药无效、之后肚脐疼”，可拆为“先前怎么样？”→“胃疼，做了胃镜。”→“后来呢？”→“药吃了没啥用，后来肚脐周围开始疼。”；不得追问原文没有答案的“有没有黑便/体重下降”等问题。
- 任何数字都需要用中文汉字输出，`text`中**不得**存在任何不属于中文字符和标点符号的内容，**不得**有任何阿拉伯数字。可以转换为口语的大概不准确表达。比如
  - "180"->"一百八"
  - "396"->"三百九四百这样子" 
  - "36.7℃"->"大概三十六度七"
- 应当交替发言，相邻的turn的`speaker`不得相同。

## 静默自检

逐句检查：它是否对应事实、合理的线下衔接或真实的沟通功能？每处“嗯/呃/……/重复/不是”是否能解释为说话人的接话、思考、回忆或澄清？不能解释就删。保留对话的个性与变化，不要输出模板化医生问答。

## Few-shot

若事实为“尿不尽、偶尔尿痛、不经常痛”，一个可接受的患者 turn 是：

```json
{"speaker":"患者","text":"就是小便老有尿不尽的感觉，有时候……会有点痛。也不是经常痛。"}
```

这保留了停顿的回忆/组织功能与“偶尔、非经常”的限定；不可写成“尿……尿不尽”或把医生的药名拆成结巴。

## 详细 few-shot：短咨询也要有可见的转写节奏

### 输入事实

患者：慢性荨麻疹是否要永远忌口；未查过过敏原；询问能否检查；担心查到后是否需要永远忌口。  
医生：可以检查过敏原；不需要永远忌口，体质会变化。

### Stage 3 中应产生的候选

```json
{"disfluency_opportunities":[
  {"turn":1,"type":"restart","reason":"患者刚开始组织主诉和饮食顾虑","optional":false},
  {"turn":3,"type":"filler","reason":"患者回忆既往是否做过检查","optional":false},
  {"turn":5,"type":"emphasis_repeat","reason":"患者对长期忌口的担忧再次强化","optional":false}
]}
```

### 错误：只有礼貌口语、没有转写质感

```text
患者：医生你好，我慢性荨麻疹，这个病是不是需要永远忌嘴啊？
医生：嗯，问你一下，你查过过敏原吗？
患者：嗯……没查过。
患者：那慢性荨麻疹可以查过敏原吗？
医生：可以，能查过敏原。
患者：哦……那要是查到过敏原的话，是不是就要永远忌口了？
医生：也不用永远忌口，体质会变化的。
患者：好，我知道了。谢谢医生。
```

这里的“嗯……”“哦……”只是礼貌性停顿，患者主诉、回忆和担忧全都过于顺滑，未落实 Stage 3 的候选。

### 正确：不增加医疗事实的转写式改写

```json
{"dialogue_id":883,"source":"","meta":{"sex":"女","age":21,"language":"Chinese"},"dialogue":[
  {"speaker":"医生","text":"你好，请坐。怎么不舒服？"},
  {"speaker":"患者","text":"医生，我这个慢性荨麻疹，就是、就是想问饮食要不要一直忌。"},
  {"speaker":"医生","text":"嗯，过敏原之前查过没有？"},
  {"speaker":"患者","text":"没……没查过。"},
  {"speaker":"患者","text":"那这种能不能查？"},
  {"speaker":"医生","text":"可以，过敏……过敏原这个能查。"},
  {"speaker":"患者","text":"哦，那要是查出来了，是不是就、就得一直忌口？"},
  {"speaker":"医生","text":"也不用一直忌，体质会变化的。"},
  {"speaker":"患者","text":"哦，行，我知道了。谢谢医生。"}
]}
```

现象与事实的对应关系：  
“就是、就是”是患者起句组织，不改变主诉；“没……没查过”保留原始否定；“就、就得一直忌口”强化原本已有的担忧；“过敏……过敏原这个能查”是医生的术语重启，但最终仍清楚表达原来的检查建议。医生有表面瑕疵，不等于可以改变医学事实。

## 保留的旧 few-shot：真实转录风格锚点

以下示例用于学习“瑕疵出现在哪里、如何随对话推进而聚集”。它们不是配额，更不能把示例中的疾病、检查、药物或追问迁移到当前输入。

### 黄金示例一：把线上材料变成线下面诊

原始线上对话中，患者说“头晕，四肢无力，容易心慌”，医生给出“气阴两虚、痰湿体质；可以中成药或熬药”，并要求患者上传舌苔照片。

可接受的线下改写片段：

```text
医生：嗯，坐吧。您这个情况啊，有点气阴两虚、痰湿体质。呃，可以喝，吃中成药，也可以自己熬点中药。
患者：哦这样。
医生：对，现在主要有哪些不舒服？
患者：就是经常头晕，四肢有点，没什么力气，还容易心慌。
……
医生：你这个心脏，唔，供血可能不太好。来，方便伸一下舌头让我看看舌苔吗？
患者：啊，好的。
医生：嗯……看了一下，可以开点中药调理一下。
```

这里“呃，可以喝，吃中成药”与“四肢有点，没什么力气”都发生在说话人组织表达的位置；“上传照片”被改为当面看舌苔。不要把这理解成医生每段都必须改口。

### 黄金示例二：长叙述的拆分与记忆障碍

原始线上长段同时包含：长期肠胃不好、胃镜提示轻微胃炎、一个月中药无效、之后服用庆大霉素/胶体果胶铋/枫蓼肠胃康等药、肚脐周围隐痛减轻、饭后不消化和轻微恶心。

可接受的线下改写片段：

```text
患者：我一直肠胃就不太好。前一阵子胃疼，去做了个胃镜，说是轻微胃炎。
医生：当时有开药吗？
患者：当时大夫建议中药调理，但我吃了一个月中药，感觉也没啥效果。后来就，肚脐眼四周就开始疼，感觉像是肠子疼。
……
患者：后来又去看了西医，给我开了庆大霉素、胶体果胶比，还有枫，我想想，一个枫字开头的药，好像还有一个治肠炎的药，也忘了。
……
患者：吃了快，呃，半个月吧，确实好多了。现在主要是肚脐，周围隐隐痛，没之前那么疼了。
```

药名模糊和“我想想”有明确来源：患者确实在回忆原文中已列出的药。它们不能用于明确、稳定的药名，也不能凭空替换为别的药。

### 真实转录观察一：头晕问诊

```text
医生：你好，乐先生对吧？我来问一下你的情况哈，你怎么不舒服啊？
患者：头晕？
医生：哦，有多久了？
患者：有一两个月了吧，两个月之前就有。
……
医生：没有是吧？当时有没有看呢？
患者：当时没看。
医生：没没看，然后怎么样就好了呢？
患者：休息休息，一下午加一晚上，我请假休息后第二天就好了。
……
医生：行。呃，最近有再发发吗？
患者：最近就就这段时间，有有个把星期吧。
```

可观察到短确认、echo、轻重复、填充词和偶发嘴瓢；它们不均匀，也不会每句话都发生。

### 真实转录观察二：结石问诊

```text
患者：就一开始我就是感觉在上班的时候胀痛胀痛的，然后一直冒冷汗，我就……就过来了。
……
患者：以前有过，但是到到输到那个输尿……输尿管里面就，我去检查，他说可以排出来。
……
患者：但是，但是已经那个转氨酶已经已经降已经……已经降到正常值了。
……
患者：啊，做过皮脂。
医生：皮皮脂。
患者：就那个什么。
医生：皮脂腺囊肿。
```

重度不流利集中于回忆、描述突发经历或词汇检索；这类真实样本只用于把握分布，不可在每个短咨询中机械复刻。

# Stage 5：Validator — 事实守门与自然度校验

审核生成结果。你要阻止事实漂移和机械表演，但不要把有创意的自然改写误判为错误。只输出 JSON。

## 输入格式

```json
{"generated_dialogue":{...},"fact_lock":{...},"turn_plan":{...}}
```

## 输出格式

```json
{
  "verdict":"pass | repair",
  "checks":[
    {"rule":"fact_faithfulness","pass":true,"violations":[]},
    {"rule":"clinical_role_and_modality","pass":true,"violations":[]},
    {"rule":"flow_similarity","pass":true,"violations":[]},
    {"rule":"functional_disfluency","pass":true,"violations":[]},
    {"rule":"long_turn_rhythm","pass":true,"violations":[]},
    {"rule":"offline_transform_and_colloquialism","pass":true,"violations":[]},
    {"rule":"short_reply_variation","pass":true,"violations":[]},
    {"rule":"creative_naturalness","pass":true,"violations":[]},
    {"rule":"format","pass":true,"violations":[]}
  ],
  "repair_targets":[{"action":"rewrite_turn | replace_text | remove_text | split_turn | merge_turn | move_turn | insert_turn","turn_index":0,"target_text":"string","instruction":"string"}]
}
```

## 判定规则

1. **fact_faithfulness**：逐项核对事实账本。新增/遗漏核心事实、否定反转、频率或确定性变化、药名错误、医生建议被改为患者陈述，均为失败。
2. **clinical_role_and_modality**：患者不能替医生下原文没有的判断；医生不能把“可以/考虑”说成“必须/确诊”。
3. **flow_similarity**：检查主问题、关键已有信息、医生回应/建议和结束意图是否仍在。允许顺序、轮数、句式和局部节奏明显不同；不得因不逐句对应或新增无医疗信息的衔接而失败。
4. **functional_disfluency**：语气词、停顿、重复、结巴、嘴瓢、无修正口误、倒装、省略表达、局部语法错误和自我修正都可出现。它们应能服务于接话、思考、回忆、顾虑、术语检索、人物习惯或真实的偶发失误；无修正口误只要上下文仍能唯一还原正确事实即可。对五个及以上实质话轮：若完全没有重启、词块重复、词汇检索、echo、倒装、省略或范围澄清，或只有“嗯/哦”而无其他可见转写现象，应标记 `repair`；修复目标是落实 Stage 3 的候选位置，而不是要求所有人使用同一种瑕疵。医生与患者都可出现这些现象。只有无动机堆叠、术语在整段中无法还原为正确事实、虚构后撤回的事实或理解变差才失败。少于五个实质话轮可全程流畅。
5. **long_turn_rhythm**：对照 `long_turn_splits`。任一超过三十五字、且承载两个以上事实组的 turn 若未拆分，标记 `repair`；优先使用 `split_turn` 或在相邻位置 `insert_turn`。插入的医生问题必须只引出后续已知事实，插入的患者回应不得增加事实。
6. **offline_transform_and_colloquialism**：检查 Stage 2 的 offline_transforms 是否全部执行。保留“上传/发照片/在线/刚在开车”等不合线下场景的远程状态或操作时标记 repair；但不能误删“开车时突然头晕”这类症状背景。对五个及以上实质话轮，若整段完全没有倒装、省略、词序重排或自然日常口语，且 Stage 2 人设允许，标记 repair，要求在合适位置作最小口语化改写。
7. **short_reply_variation**：相邻三个短确认/承接 turn 若机械重复“好”“嗯好”“知道了”或同一固定回复，标记 repair；要求按上下文替换为不新增事实的自然短回应。不得仅因出现一次“好”或“嗯”而报错。
5. **creative_naturalness**：若生成结果仍像逐条改写线上聊天、话轮机械对称、每句都同一种语气词，标记 repair；修复目标应是更自然的重组或删除模板痕迹，不能要求增加固定数量的口误。
6. **format**：检查 JSON、speaker、线下措辞、阿拉伯数字是否已经**全部**转换为中国汉字写法、括号动作说明和单 turn 六十字限制。
   1. 不应该存在任何阿拉伯数字和非中文标点符号，比如温度符号。
